Operator-adjacent item in scope:

- **MikroTik RouterOS "MikroTrick" chain — CVE-2026-67276 + CVE-2026-86060 — mass unauth-RCE exploitation continues.** [CRITICAL] CVE-2026-67276 (CVSS 9.2): SSH pubkey-auth bypass — RouterOS verifies key type and modulus but not the exponent, so an attacker knowing an authorized RSA modulus can present a key with exponent 1, forge a valid signature and open an SSH channel as the target user without holding the private key. CVE-2026-86060 (CVSS 9.2): SSH argument-handling flaw in the login path when the username begins with a prohibited character, allowing the RouterOS policy mask to be flipped mid-authentication → privilege escalation. Chained together: unauth → root, no credentials required, no user interaction. Fixed in 6.49.21 (LT), 7.23.4 (LT), 7.24.2 (stable), 7.25b3 (all 2026-09-03). Active mass exploitation observed since 2026-09-02 08:00 UTC from `82.192.72.4`; hosts-of-record IoC is creation of an `ops` account by a rogue user account named `0` (log line contains `ssh:-2@`). ~300k vulnerable devices reachable per Shodan. Impact for a telco offensive-security practitioner: MikroTik CCR/CRS/hEX gear sits behind a lot of WISP subscriber-edge, MVNE bespoke aggregation, small-cell/DAS transport, private-LTE/-5G perimeter, and mid-market MPLS-CE fleets; any operator-network audit that assumed vendor-managed edge routers were out of scope needs a rescope. Not KEV-listed at end of in-window. [CERT Polska advisory (2026-09-05)](https://cert.pl/en/posts/2026/09/vulnerabilities-in-mikrotik-routeros-actively-exploited/) · [MikroTik supportsec advisory](https://mikrotik.com/supportsec/september-2026-vulnerability/) · [The Hacker News](https://thehackernews.com/2026/09/attackers-hijack-mikrotik-routers.html) · [SecurityAffairs (IOC guide — SSH user "-2")](https://securityaffairs.com/198538/security/your-mikrotik-router-may-already-be-compromised-look-for-ssh-user-2.html) · [AiCybr breakdown](https://aicybr.com/blog/mikrotik-routeros-mikrotrick-active-exploitation) — day-2 in scope
