# Security digest — 2026-09-02

Window: 2026-09-01 04:00 UTC → 2026-09-02 04:00 UTC.

## TL;DR
- **Critical JFrog Artifactory auth-bypass (CVE-2026-82329, CVSS 9.8) is now under active mass exploitation.** WatchTowr, Dark Reading and multiple independent trackers observed attackers "minting themselves admin tokens" against internet-exposed Artifactory instances beginning 2026-09-01, four days after JFrog's disclosure. This is a build/artefact-repo takeover primitive — any downstream package the victim publishes should be treated as suspect. Self-hosted operators must be on 7.111.21 / 7.117.28 / 7.125.20 / 7.133.29 / 7.146.38 / 7.161.20 immediately.
- **BGP hijack of Softaculous / Virtualizor's update infrastructure delivered a malicious Virtualizor update to VPS hosts (2026-08-28 → 2026-08-30, disclosed 2026-09-01).** AS62390 (NexonHost) announced 162.55.80.0/24 via AS6204 (Zet.net) for ~33 hours, intercepted Let's Encrypt validation to obtain valid certs for `virtualizor.com` / `api.virtualizor.com` / `files.virtualizor.com`, and pushed a poisoned update to hosts that checked in during the window. Fixed in Virtualizor 3.2.9.9 (2026-09-01) with a new "Security Analyzer"; package signing is being retrofitted after the fact. Real-world reminder that TLS + AS-path trust ≠ update-channel integrity.
- **CISA KEV added two PaperCut NG/MF zero-days (CVE-2026-81578, CVE-2026-82078) on 2026-08-31 with a 2026-09-14 federal deadline.** Chained, they give pre-auth RCE on the PaperCut Application Server. PaperCut released a second emergency patch. On the KEV window, this is the fresh compulsory-remediation entry.
- **Langflow (CVE-2026-0768, CVSS 9.8) and Ruby on Rails / KindaRails2Shell (CVE-2026-66066, CVSS 9.5) are both under in-the-wild exploitation — VulnCheck canaries hit 2026-09-01.** Langflow → unauthenticated Python RCE in the custom-component editor; Rails → arbitrary file read via Active Storage + libvips discrepancy, leaking `secret_key_base` and cloud/API secrets to full RCE. Attacker traffic in the Rails case originated from a French IP with C2 to Israel.
- **Telecom side of the day is quiet on primary sources.** No new in-window GSMA FS.11 / T-ISAC, 3GPP SA3, or Ericsson / Nokia / Mavenir / Oracle Communications PSIRT advisories located. Cisco's PSIRT batch scheduled for 2026-09-02 (today) will include the **IOS XR security-hardening release** — in the wake of last week's Fire Ant / IOS XR disclosure it is the priority item to pull as soon as it lands.

## General high-severity

- **JFrog Artifactory CVE-2026-82329 — authentication bypass, CVSS 9.8, active in-the-wild exploitation as of 2026-09-01.** [CRITICAL] Improper-authentication flaw (CWE-287) in Artifactory's default configuration; a remote, unauthenticated attacker gains administrator-level access with no user interaction. WatchTowr observed attackers minting themselves admin tokens; The Hacker News, SecurityWeek, Dark Reading and The Register all reported in-window active exploitation, with attackers enumerating users, groups, credential sets and federated access topologies once admin is obtained. Disclosure by JFrog was 2026-08-28; exploitation surfaced ~4 days later. Cloud instances patched; self-hosted must upgrade to **7.111.21, 7.117.28, 7.125.20, 7.133.29, 7.146.38, or 7.161.20**. Practitioner impact: Artifactory is often the pivot between developer laptops, CI/CD runners and production package publishing — assume any post-compromise-published artefact is untrusted until proven otherwise. [The Hacker News](https://thehackernews.com/2026/09/attackers-exploit-critical-jfrog.html) · [SecurityWeek](https://www.securityweek.com/critical-jfrog-artifactory-vulnerability-reportedly-exploited-in-the-wild/) · [Dark Reading](https://www.darkreading.com/application-security/attackers-pounce-critical-artifactory-flaw-disclosure) · [The Register](https://www.theregister.com/security/2026/09/01/another-artifactory-cve-under-attack-by-ai-agents-or-humans/5293769) · [Cyber Security News](https://cybersecuritynews.com/jfrog-artifactory-auth-bypass-exploited/) — 2026-09-01
- **Softaculous / Virtualizor — BGP hijack of update infrastructure delivered malicious update.** [CRITICAL] Between 2026-08-28 20:57 UTC and 2026-08-30 06:10 UTC, AS62390 (NexonHost) originated an unauthorised announcement of `162.55.80.0/24` (Softaculous / Hetzner space) via AS6204 (Zet.net). The hijack diverted HTTP-01 validation to attacker-controlled infrastructure, allowing them to obtain **valid Let's Encrypt certificates** for `virtualizor.com`, `api.virtualizor.com` and `files.virtualizor.com`; Virtualizor installations that checked for updates during the window over apparently valid HTTPS received a malicious update package. Softaculous released Virtualizor 3.2.9.9 on 2026-09-01 with a "Security Analyzer" tool for admins to check for compromise, and committed to cryptographically signing all future packages. Detection: audit for out-of-cycle Virtualizor update fetches in that window; verify installed binary hashes against 3.2.9.9. Practitioner-visible reminder that a valid Let's Encrypt cert is not proof of update-channel authenticity if BGP is hostile. [BleepingComputer](https://www.bleepingcomputer.com/news/security/hackers-push-malicious-virtualizor-update-in-bgp-hijacking-attack/) · [The Register](https://www.theregister.com/security/2026/09/01/33-hour-bgp-hijack-of-softaculous-traffic-prompts-security-scramble/5293608) · [Virtualizor blog (primary)](https://www.virtualizor.com/blog/security-incident-bgp-hijacking/) · [Cyber Security News](https://cybersecuritynews.com/virtualizor-compromise/) — 2026-09-01
- **CISA KEV — PaperCut NG/MF added: CVE-2026-81578 + CVE-2026-82078 (2026-08-31, federal deadline 2026-09-14).** [HIGH] Missing-Authentication + Unsafe-Reflection pair that can be chained to give unauthenticated attackers pre-auth RCE on the PaperCut Application Server. PaperCut released an urgent second emergency patch. Reported active exploitation. CISA BOD 26-04 forces federal-agency remediation by 2026-09-14; private-sector operators should treat the same deadline as a hard target. Any PaperCut instance directly exposed to the internet should be assumed compromised and rebuilt from a known-good baseline, not merely patched. [CISA KEV](https://www.cisa.gov/known-exploited-vulnerabilities-catalog) · [Security Affairs](https://securityaffairs.com/198200/security/u-s-cisa-adds-papercut-ng-mf-flaws-to-its-known-exploited-vulnerabilities-catalog.html) · [Cyber Security News](https://cybersecuritynews.com/papercut-ng-mf-vulnerabilities-exploited/) · [SecurityWeek](https://www.securityweek.com/papercut-exploitation-escalates-to-active-intrusions/) — added 2026-08-31, in-window coverage 2026-09-01
- **Langflow CVE-2026-0768 (CVSS 9.8) and Ruby on Rails CVE-2026-66066 / "KindaRails2Shell" (CVSS 9.5) — both actively exploited.** [HIGH] VulnCheck published in-window observation of active exploitation. Langflow: insufficient validation of a user-supplied parameter in the custom-component editor lets an unauthenticated attacker run arbitrary Python as root; observed attempts to read `/root/.cache/langflow/secret_key`, enumerate SSH access, and stat `.bash_history`. Rails: discrepancy between Active Storage and libvips in how each parses images allows a crafted image upload to trigger arbitrary file read, leak `secret_key_base` / DB / cloud credentials / API tokens, and escalate to RCE. VulnCheck's canaries in Singapore, Israel and the UK were hit from a single French IP, with C2 to Israel. Practitioner impact: audit inbound to internal AI-app hosting stacks — Langflow is a common component in enterprise AI-agent pilots and is frequently exposed to more of the network than the operator realises. [The Hacker News](https://thehackernews.com/2026/09/attackers-exploit-critical-langflow-and.html) · [Cyber Security News](https://cybersecuritynews.com/langflow-rce-and-rails-vulnerability-exploited/) · [CyberPress](https://cyberpress.org/hackers-exploit-critical-langflow-and-ruby-on-rails-flaws/) — 2026-09-01
