## Telecom

- **Arista VeloCloud Orchestrator CVE-2026-16812 — CVSS 10.0 unauthenticated OS command injection, exploited in the wild, patched 27 Jul, KEV-listed same day. Directly relevant to operators running VeloCloud-based managed SD-WAN.** The flaw allows a remote unauthenticated attacker to reach VCO functionality that was intended for internal use only but remained remotely accessible, resulting in OS command execution on the orchestrator host and compromise of confidentiality, integrity and availability of the orchestrator and every SD-WAN edge under its control. Arista's Security Advisory 0144 landed on 27 Jul and CISA added CVE-2026-16812 to KEV the same day. Fixed in VCO 5.2.3.14, 6.1.3.4, 6.4.2.4 and 7.0.0.1 (7.0.0.1+); Hosted and Dedicated Arista-managed VCO tenants were patched before public disclosure. Arista disclosed the flaw was found externally and is under active exploitation but did not publish attribution, timeline of first exploitation, or IOC set. For a telco offering SD-WAN as a service on top of VeloCloud, the orchestrator is a crown-jewel control plane — compromise there is compromise of the customer WAN estate. For a telco simply using VeloCloud as its own WAN, same argument at smaller blast radius. Practical read: patch immediately if on-prem, verify with Arista if under managed contract, and treat any pre-patch on-prem VCO exposed to the internet as compromised rather than merely vulnerable. [CISA KEV alert](https://www.cisa.gov/news-events/alerts/2026/07/27/cisa-adds-two-known-exploited-vulnerabilities-catalog), [Arista SA-0144](https://www.arista.com/en/support/advisories-notices/security-advisory/24364-security-advisory-0144), [BleepingComputer](https://www.bleepingcomputer.com/news/security/arista-patches-velocloud-orchestrator-zero-day-exploited-in-attacks/), [Intruder CVE profile](https://cvemon.intruder.io/cves/CVE-2026-16812). ## General high-severity

- **CISA KEV addition — CVE-2025-68686 Fortinet FortiOS SSL-VPN "symlink persistence" patch-bypass, exploited in the wild.** Added to KEV 27 Jul. The vulnerability is a bypass of the mitigation Fortinet developed against the symlink-persistence post-exploitation technique that surfaced in the wake of the CVE-2022-42475 / CVE-2023-27997 / CVE-2024-21762 SSL-VPN mass-exploitation waves — that mitigation restored a symbolic link created by attackers as a persistence artefact, and CVE-2025-68686 lets an unauthenticated remote attacker re-establish that persistence via crafted HTTP requests. Requires that the target was previously compromised through one of the underlying SSL-VPN CVEs, i.e. this is a persistence-restoration primitive rather than a first-stage RCE, but for anyone whose SSL-VPN was ever exploited in the earlier waves and who trusted the earlier patch to have cleaned up, the KEV listing today is the cue to re-hunt. Affected: FortiOS 6.4 all, 7.0 all, 7.2 all, 7.4.0-7.4.6, 7.6.0-7.6.1. Fixed: 7.4.7+, 7.6.2+. Products that never had SSL-VPN enabled are unaffected. Fortinet PSIRT advisory FG-IR-25-934 was originally published 10 Feb 2026 and had received limited attention until the KEV promotion today. [CISA KEV alert (27 Jul)](https://www.cisa.gov/news-events/alerts/2026/07/27/cisa-adds-two-known-exploited-vulnerabilities-catalog), [FortiGuard PSIRT FG-IR-25-934](https://fortiguard.fortinet.com/psirt/FG-IR-25-934), [SecurityWeek Fortinet patches roundup](https://www.securityweek.com/fortinet-patches-high-severity-vulnerabilities/), [GitHub Advisory GHSA-839g-m33x-3w78](https://github.com/advisories/GHSA-839g-m33x-3w78). Date: 2026-07-27. [HIGH]

- **vBulletin CVE-2026-61511 — pre-auth PHP RCE via `runMaths()` eval() sink, public PoC released 27 Jul.** SSD Secure Disclosure published the vulnerability details and a working exploit on 27 Jul, nearly four weeks after vBulletin quietly shipped fixed builds (6.2.1, 6.2.0, and 6.1.6 patched end-June; 6.2.2 released 1 Jul). Root cause: `vB5_Template_Runtime::runMaths()` in `/includes/vb5/template/runtime.php` implements the `{vb:math}` template tag by regex-filtering the input then passing the filtered string to PHP's `eval()`. The regex admits digits, parentheses, arithmetic operators, binary operators, and the XOR operator — enough surface for an unauthenticated attacker to construct expressions that break out into arbitrary PHP execution on the forum host. No admin session, no authenticated user, no user interaction required. Affected: 6.2.1 and earlier, 6.1.6 and earlier. Any forum still on those branches as of today should be assumed compromised, not merely vulnerable, given the ~4-week PoC clock and the historic pattern for vBulletin RCEs being ingested into commodity mass-scanners within days. [The Hacker News](https://thehackernews.com/2026/07/public-exploit-released-for-patched.html), [SSD Secure Disclosure original](https://ssd-disclosure.com/vbulletin-runtime-template-runmaths-preauth-rce/), [Cybersecurity News](https://cybersecuritynews.com/vbulletin-flaw-execute-php-code/), [GBHackers](https://gbhackers.com/vbulletin-pre-auth-rce-flaw/). Date: 2026-07-27. [HIGH]

## Worth watching

- **TELESHIM / MIXEDKEY / BINDCLOAK — Zscaler ThreatLabz on East-Asia-linked APT campaign against Middle East government.** Zscaler blog and press wave landed into today's window (The Hacker News 27 Jul, GBHackers 27 Jul, Security Boulevard 27 Jul); underlying research authored by Sudeep Singh's team at Zscaler. Chain: weaponised ISO drops a legitimately-signed ASUS binary (`RegSchdTask.exe`) that DLL-sideloads `AsTaskSched.dll` and stages TELESHIM (Telegram-API-based C2, blending in with legitimate Telegram traffic), MIXEDKEY, and BINDCLOAK. Notable technique choices: heavy control-flow flattening / mixed-boolean-arithmetic / opaque-predicate obfuscation, and environmental keying — BINDCLOAK is encrypted with a key derived from the target machine's NTFS volume serial number so payload analysis on any other host fails to decrypt. Targeting: government entities in the Middle East. Not a telco-plane item but the "abuse a legitimate messaging API for C2" pattern generalises to any messaging platform (WhatsApp, Signal via bridges, Discord) and is worth threat-modelling against for any environment where Telegram traffic is not by default suspicious. [The Hacker News](https://thehackernews.com/2026/07/teleshim-abuses-telegram-for-c2-in.html), [Zscaler ThreatLabz Part 1](https://www.zscaler.com/blogs/security-research/targeted-attack-government-entities-middle-east-part-1), [Security Boulevard mirror](https://securityboulevard.com/2026/07/targeted-attack-on-government-entities-in-the-middle-east-part-1/), [GBHackers](https://gbhackers.com/hackers-hide-c2-traffic-inside-telegram/), [CyberPress](https://cyberpress.org/teleshim-targets-middle-east-governments/).
