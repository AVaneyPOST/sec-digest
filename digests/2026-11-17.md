**Check Point PHP2Shell → `destroy_v6` wiper chain — vendor technical writeup now public** · [CRITICAL]
In-window vendor technical writeup. Research.checkpoint.com published "PHP2Shell Exploitation on Check Point Gateway" covering the full chain: **PHP2Shell (CVE-2026-109618 / CVE-2026-109619)** unauthenticated RCE against the Mobile Access portal on R80–R82.20 → **CVE-2026-123039** (yesterday's KEV deadline) Gaia DynamicCLI world-writable local socket → local root → **TSGA** backdoor + **TSProxy** proxy (both PhiliKit-family tooling, which has prior China-nexus UNC5221 overlap; Check Point explicitly declines attribution and notes the political note + Israeli-only victimology don't fit UNC5221 profile) → `gogo` scanner for lateral discovery → SSH from the gateway to VMware ESXi hosts under the `vpxuser` service account → `destroy_v6` ELF wiper against datastores → `DREAM_ANNEXATION.txt` note that explicitly rejects ransom negotiation. First-wave targeting began **2026-10-30** against Israeli organisations; Check Point counts a couple of dozen compromised unpatched gateways in-region. Infrastructure note: LightNode VPS, scanning window 00:00–09:00 UTC (loose Chinese-working-hours signal; weak attribution evidence). **Fix**: Install the November Jumbo Hotfix on all Management and Security Gateways; prioritise internet-facing Mobile Access portals; verify no gateway can SSH to ESXi as `vpxuser`; confirm offline ESXi backups; hunt `DREAM_ANNEXATION.txt`, unexpected `vpxuser` SSH sessions originating from Check Point gateways, and unexpected writes to the DynamicCLI socket path. **Telecom angle**: Check Point gateways sit on operator-IT DMZ, M2M management, some S-GW / vendor-support jump paths; ESXi is the fabric for virtualised OSS/BSS, vSBC, HSS and 5G-SBA workloads, and a gateway-to-ESXi SSH as `vpxuser` is the single most common virtualisation-fabric topology. The destructive leg is new against this vendor; last year's vSphere-worm patterns stopped at ransomware, not wiper.
