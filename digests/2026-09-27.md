Network IOCs: `5.199.162.157`, `104.219.234.138`, `162.219.30.165` (SIDEEYE C2 TCP/3333 control, TCP/3334 data); staging domains `azurenetfiles.net`, `microsoft-entra.net`, `enroll.azuredevice.cloud`, `winmanage-me.network`. **Carrier relevance:** PeopleSoft HCM / Campus / Financials estates that touch employee data, benefit portals, or billing consolidation at telco holding companies. Not signalling, but plenty of carrier B2B microsites, partner portals, MVNO / device-marketplace storefronts and dev-team blogs sit on Elementor; sweep alongside the CVE-2026-87902 WordPress-Core work. - **SiYuan CVE-2026-100646 (CVSS 8.1) — published 2026-09-26 inside window.** Self-hosted personal knowledge-management system; the kernel's auth guard fails open when the HTTP `Origin` header is absent (assumption: any cross-site browser request carries `Origin`, which is not true for cross-site top-level GETs or `no-cors` subresource loads). Session cookie is `SameSite=Lax`, so a single cross-site GET from an attacker's page is granted `RoleAdministrator` on default installs **and** on password-protected instances with a live session. Chained with content-type sniffing on `/api/network/proxy`, this yields unauth remote script exec in the SiYuan origin (`http://127.0.0.1:6806`), admin-API invocation, and persistent kernel-API-token exfil. Fixed in 3.8.4. Not carrier-signalling, but SiYuan is used inside SRE / knowledge / runbook wikis, so worth an internal inventory query for anyone who has it on the corp LAN. [strix.ai — CVE-2026-100646](https://www.strix.ai/cve/CVE-2026-100646) · [OffSeq Threat Radar — CVE-2026-100646](https://radar.offseq.com/threat/cve-2026-100646-origin-validation-error-in-siyuan-note-siyuan-2530c93713e2df7c) — 2026-09-26 — NOTABLE
