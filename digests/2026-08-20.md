## Telecom

**Cisco PSIRT — August 19, 2026 batch published (telecom-relevant advisories)** — [Cisco advance notice (LDquvx5d)](https://sec.cloudapps.cisco.com/security/center/content/CiscoSecurityAdvisory/cisco-sa-notice-LDquvx5d), [NVD — CVE-2026-20320](https://nvd.nist.gov/vuln/detail/CVE-2026-20320), [NVD — CVE-2026-20314](https://nvd.nist.gov/vuln/detail/CVE-2026-20314), [NVD — CVE-2026-20327](https://nvd.nist.gov/vuln/detail/CVE-2026-20327), [SentinelOne DB — CVE-2026-20055](https://www.sentinelone.com/vulnerability-database/cve-2026-20055/) — 2026-08-19 — **HIGH**
The Wednesday batch published on schedule (~16:00 UTC 2026-08-19). The four telecom-adjacent items:
- **CVE-2026-20320 — Cisco BroadWorks OCI XML parser Blind XXE (Out-of-Band).** OCI is BroadWorks' primary management/provisioning interface exposed on carrier hosted-UC/VoLTE deployments. The blind XXE is out-of-band delivery — attacker plants a payload that causes the parser to fetch an attacker-controlled URI (HTTP/FTP), yielding SSRF, internal-network probing, and (via DTD tricks) filesystem read of BroadWorks configuration/credentials without a direct-response channel. High severity, data-exfiltration primitive for carrier OSS/BSS pivoting. Authentication requirement + affected versions to be re-verified against the published advisory ladder; treat as a red-team lateral primitive once inside a carrier's OSS enclave, and as a perimeter-reachable primitive if OCI is on the internet edge (it should not be — audit).
- **CVE-2026-20314 — Packaged Contact Center Enterprise / Unified CCE SSRF (authenticated).** Contact-centre plane rather than signalling plane, but still carrier-relevant for wholesale IVR / hosted CCaaS operators. Authenticated SSRF lets an inside-attacker route through the CCE server to reach otherwise-firewalled backend services — good pivot for a foothold hoping to reach the BroadWorks / voice-core LAN.
- **CVE-2026-20055 — Packaged CCE / Unified CCE web management stored XSS (authenticated admin).** Lower priority; admin-privileged prerequisite makes this a persistence / privilege-hijack helper rather than a fresh initial-access vector.
- **CVE-2026-20327 — Cisco Unified Intelligence Center blind SQL injection (authenticated).** CUIC is the reporting front-end for UCCE/PCCE; the blind SQLi against the web management interface gives credential/data access from an authenticated (typically operator/analyst-role) foothold. Same admin-adjacent risk profile as CVE-2026-20055.

None of the four are known exploited in the wild. No CVSS 9.8s in the telecom subset of this batch (the Cisco August 5 IOS XE / SD-WAN hardening bundle carried the 9.8s; today's is a milder batch). Non-telecom items in the same batch: **Crosswork software hardening bundle** (internally-discovered vulnerabilities, not ITW), **Industrial Ethernet 1000 Series** (OT-adjacent), **RoomOS** (enterprise collab), **Secure Workload** (workload-microsegmentation). Advisory URLs settle on `sec.cloudapps.cisco.com` under `cisco-sa-broadworks-*`, `cisco-sa-ucce-pcce-*`, `cisco-sa-cuic-*` — pull from the publication listing for exact fix ladders.

## General high-severity

**Fastjson 1.x — CVE-2026-16723 (CVSS 9.0, unauth RCE) — active-exploitation reporting broadens** — [SecurityWeek — Unpatched Fastjson exploited](https://www.securityweek.com/unpatched-fastjson-vulnerability-exploited-in-attacks/), [Imperva blog — CVE-2026-16723 protection](https://www.imperva.com/blog/imperva-customers-protected-against-cve-2026-16723-critical-fastjson-1-x-zero-day-rce/), [CSA labs — Fastjson research note](https://labs.cloudsecurityalliance.org/research/csa-research-note-fastjson-1x-zero-patch-rce-cve-2026-16723/), [The Hacker News — Fastjson 1.x RCE (2026-07)](https://thehackernews.com/2026/07/fastjson-1x-rce-vulnerability-targeted.html) — original disclosure 2026-07; **in-window today: coverage/telemetry broadening, still no patch** — **CRITICAL**
Fastjson 1.x hit a stock-default-configuration unauth RCE (no AutoType enablement, no classpath gadget) via a @JSONType annotation trust-signal bypass under Spring Boot fat-jar deployments (i.e. the most common Java packaging model). Attacker traffic sources: ~70% browser-impersonator user-agents, ~30% Ruby/Go tooling. Targeting concentrates on US business, financial services, healthcare, computing, retail; Singapore and Canada also hit. **Fastjson 1.x is EOL — no vendor patch is coming.** Mitigations: migrate to Fastjson 2.x (semver-breaking API changes), enable **SafeMode** on 1.x, block the malicious payload class prefix at WAF, or ship an internal-fork patch removing AutoType. Practical impact for a red-teamer: any Java Spring Boot fat-jar reachable from the internet is a candidate — enumerate `X-Powered-By`, `Server`, error-page fingerprints, `.jar`-detection endpoints. This is a genuine long-tail unpatched enterprise-Java RCE for the remainder of 2026.
