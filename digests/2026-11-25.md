# Security digest — 2026-11-25

Window: 24 hours ending 2026-11-25 ~04:00 UTC. A more active cycle than Mon→Tue. CISA added three fresh KEVs on 2026-11-24 (all deadline 2026-11-27), Radware disclosed a Cloud WAF management-API exposure that leaked customer cloud storage credentials, N-able patched the critical SSRF (CVE-2026-134624) that CISA had KEV-listed one day earlier, and Chrome shipped an emergency fix for a critical sandbox-escape bug. Telecom-side the material item is the India TDSAT ruling making a mobile operator liable for downstream bank fraud from a SIM swap — regulatory, not a CVE, but it rebalances operator exposure. No new SS7/Diameter/GTP CVEs in-window.

## TL;DR

- **CISA KEV — 3 additions 2026-11-24, federal deadline 2026-11-27 (two days out).** Drupal Core RCE `CVE-2026-132165` (SA-CORE-2026-017, exploited on live sites from Nov 19, fixed in 10.6.22 / 11.3.22 / 11.4.13), Idunno AntiCsrf deserialization `CVE-2026-131914` (CVSS 9.8, Mandiant observed exploitation, vendor guidance = remove the library), and Optimizely Web Experimentation `CVE-2026-132224` (card-skimmer insertion via signup-flow abuse 2026-11-16, hosted service already fixed).
- **Radware — breach confirmed 2026-11-24 (incident 2026-11-19).** An unauthenticated internal Cloud WAF management API, exposed to the public internet, let an attacker pull customer log-export credentials: AWS S3 keys, Azure Blob keys/SAS tokens, SFTP creds. ~10h window before Radware shut it off. Customers already seeing AWS alerts for an unfamiliar IP hitting their log-export buckets. Rotate anything configured for log export since 2026-11-19.
- **N-able Mail Assure — critical SSRF `CVE-2026-134624`, CVSS 4.0 9.3, KEV 2026-11-23, patched 2026-11-21 (build 20261121.1943).** Discovered by N-able during the Nov 16 Hosted Cloud intrusion investigation; its role in that intrusion is still unknown. LDAP sync connection check had no destination restriction → authenticated API user can pivot the Mail Assure appliance at arbitrary internal hosts/ports. Advisory does not claim code execution.
- **Chrome `CVE-2026-134401` — critical sandbox escape, CVSS 9.6, emergency fix in 158.0.8127.88 (Nov 23).** Improper input validation in the Variations component; crafted HTML page → code execution outside the sandbox. No confirmed in-the-wild exploitation; found internally by Google researchers 2026-08-28. 8th or 9th critical Chrome patch of 2026 depending on how you count — notable because it's the Variations service pipeline, not the usual V8/renderer path.
- **India TDSAT — operator liable for SIM-swap bank fraud (2026-11-24).** Ruling ordered Vodafone Idea to implement secure subscriber verification and held the operator liable for downstream losses. Regulatory precedent; sets the stage for the FCC SIM-swap/port-out rules whose compliance deadline is 2026-12-17 (22 days out).
- **No new SS7 / Diameter / GTP / N32 CVEs in-window.** No new PSIRT advisories from Cisco, Ericsson, Nokia, Mavenir, or Oracle Communications surfaced today. The signalling-plane story remains SilentAir / LIMINAL PANDA / GTPDoor as continuing coverage.

## Telecom

- **India TDSAT ruling — mobile operator liable for SIM-swap→bank-fraud losses (2026-11-24).** Telecom Disputes Settlement and Appellate Tribunal held Vodafone Idea liable for consequential bank fraud following a SIM swap and ordered it to implement secure subscriber verification. **Why it matters:** this is one of the first appellate-tribunal rulings putting the operator on the hook for downstream account takeover losses, not just the portability event itself. The practical knock-on for red teams is that ops at lagging operators now have budgetary cover to actually fix port-out / SIM-change workflows, which will compress the window for insider-assisted SIM swap tradecraft at those carriers. Pair with the FCC rule effective 2026-11-17 and the compliance deadline 2026-12-17. [[LegalDeli summary](https://legaldeli.in/blog/legal/tdsat-a-mobile-co-is-liable-for-sim-swap-consequential-bank-fraud)] · 2026-11-24 · **NOTABLE**
- **N-able Mail Assure SSRF `CVE-2026-134624` — telecom-adjacent, MSP infra plane.** CVSS 4.0 9.3; KEV 2026-11-23; patched build `20261121.1943`. LDAP-sync connection check in the mail-relay config path had no destination restriction → authenticated API user can target internal hosts/ports. Advisory doesn't claim RCE. Found by N-able during the Nov 16 Hosted Cloud intrusion investigation; its role in that intrusion remains unresolved. **Why it matters:** MSP mail-security plane sits beside carrier/hosted-voice infrastructure in a lot of mid-market stacks — the operator-tier blast radius here is the MSP customers downstream, not direct subscriber signalling. [[The Hacker News](https://thehackernews.com/2026/11/n-able-discloses-critical-mail-assure.html)] [[SecurityWeek](https://www.securityweek.com/n-able-patches-critical-flaw-disclosed-after-mail-assure-cyberattack/)] [[Cybersecurity News](https://cybersecuritynews.com/critical-n-able-mail-assure-ssrf-vulnerability/)] · 2026-11-23 KEV, 2026-11-27 federal deadline · **HIGH**

Still the US-side regulatory clock that matters for carriers without hardened port-out and SIM-change workflows. Pair with the India TDSAT item above; both are pressure vectors on the same operator workflows.
