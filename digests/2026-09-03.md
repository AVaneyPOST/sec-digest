## TL;DR
- **Cisco's 2026-09-02 PSIRT batch is a telecom day.** The Nexus 9000 Silicon One integration ships an **unauthenticated remote-root RCE (CVE-2026-20212, CVSS 9.8)** on TCP 43210/43211 exposed in the default L3 VRF — a datacentre/carrier-fabric primitive. The IOS XR **Security Hardening Release: September 2026** lands the first bundle of internally-found IOS XR CWE-grouped CVEs (CVE-2026-20274, CVE-2026-20278 among them; not known-exploited) — post-Fire-Ant, this is the priority IOS XR pull. A separate SIP-phone advisory covers Desk Phone 9800 / IP Phone 7800 / 8800 / Video Phone 8875 with unauth arbitrary file-write + info-disclosure via directory-permissions bugs (mitigated by default because Web Access is off).
- **Sangoma Switchvox CVE-2026-9586 is on CISA KEV today (2026-09-02) after honeypot hits from 2026-08-30.** Unauthenticated SQL injection on `/pa` (Polycom IP-phone provisioning endpoint) → arbitrary PostgreSQL → reverse shell on the PBX. Patched 2026-07-14 in Switchvox SMB 8.4.0.2; ~4,000 instances still exposed on Shodan, mostly U.S. Any operator with an on-prem Switchvox PBX is a direct target now.
- **SonicWall SMA1000 zero-day chain (CVE-2026-83548 CVSS 10.0 pre-auth SSRF + CVE-2026-83549 CVSS 7.8 post-auth OS-command injection) actively exploited; hotfix 2026-09-02.** Third distinct zero-day wave against SMA1000 in under a year, all against 6210 / 7210 / 8200v. Attackers deploy custom ROOTRUN (setuid ELF), KNUCKLEBALL (Python JVM injector) and ORANGETAIL (Java web shell); INC Ransomware is the dominant actor. Both CVEs on CISA KEV. Patch to 12.4.3-03526 or 12.5.0-02952 and assume compromise — July's stolen TOTP MFA seeds outlast the patch.
- **CISA KEV added seven CVEs today (2026-09-02)**: Sangoma Switchvox 9586, Starlette host-header 48710, Kestra 49869, BerriAI LiteLLM 59822, JFrog Artifactory 82329 (yesterday's mass-exploit story now officially KEV), and both SonicWall SMA1000 CVEs (83548, 83549). Standard 21-day federal remediation clock → 2026-09-23.
- **The AI-gateway exploitation cluster Microsoft flagged on 2026-08-26 (LiteLLM + Starlette host-header bypass → unauth RCE; Kestra auth-bypass → workflow-driven shell) is now formally KEV, i.e. federal-agency compulsory remediation.** If you host any of LiteLLM, Kestra or a RAGFlow gateway internally, treat those endpoints as internet-adjacent and revoke every stored model-provider API key on any host that had them exposed before patching.

## Telecom

- **Cisco Nexus 9000 Silicon One Remote Code Execution — CVE-2026-20212, CVSS 9.8.** [CRITICAL] Unauthenticated remote attacker gains code execution as root on affected Nexus 9000 switches because TCP ports 43210 and 43211 are accessible in the default Layer 3 VRF and the S1HAL process accepts crafted input on them. Exploitation can also crash S1HAL and force a reload. This is the highest-severity Cisco advisory in today's batch and is directly relevant to any operator running Nexus 9000 in an SP-fabric, mobile-transport or aggregation role. Published 2026-09-02. Not known to be publicly exploited at publication, but the CVSS 9.8 unauth-RCE profile on a widely-deployed switch platform is treated as CRITICAL on its own. [Cisco advisory (cisco-sa-n9k-s1-rce-EH8dEtr)](https://sec.cloudapps.cisco.com/security/center/content/CiscoSecurityAdvisory/cisco-sa-n9k-s1-rce-EH8dEtr) · [OffSeq](https://radar.offseq.com/threat/cve-2026-20212-binding-to-an-unrestricted-ip-address-in-cisco-cisco-nx-os-software-1519dc1b9d3b58c9) · [ThreatINT](https://cve.threatint.com/CVE/CVE-2026-20212) — 2026-09-02
- **Cisco IOS XR Software Security Hardening Release: September 2026.** [HIGH] Internal Cisco engineering review producing a bundle of CWE-grouped CVEs (at least CVE-2026-20274, CVE-2026-20278 disclosed publicly so far); Cisco assigned one CVE ID per CWE grouping and states none are known to be actively exploited. There are no workarounds — fixed IOS XR trains only. Practitioner impact: post-Fire-Ant, an IOS XR hardening release is exactly the class of update a carrier network-engineering team wants to stage first, both because it is the first structured hardening bundle since Sygnia's disclosure and because internal Cisco review is likely to have targeted the same code paths (syslog, TACACS integration, CLI hooks) that Fire Ant abused. [Cisco advisory (cisco-sa-hardening-iosxr-qg64NcM)](https://sec.cloudapps.cisco.com/security/center/content/CiscoSecurityAdvisory/cisco-sa-hardening-iosxr-qg64NcM) · [Cisco IOS XR advisory index](https://www.cisco.com/c/en/us/support/ios-nx-os-software/ios-xr-software/products-security-advisories-list.html) · [OffSeq CVE-2026-20278](https://radar.offseq.com/threat/cve-2026-20278-improper-neutralization-in-cisco-cisco-ios-xr-software-d939778185be6617) — 2026-09-02
- **Sangoma Switchvox CVE-2026-9586 — unauthenticated SQL injection → RCE on SMB PBX; on CISA KEV today.** [CRITICAL] The `/pa` endpoint (Polycom IP-phone provisioning) accepts an XML payload; when it begins with `<PolycomIPPhone>`, the handler extracts the `PhoneIP` attribute or child value and concatenates it verbatim into a PostgreSQL query. Unauthenticated attackers can therefore run arbitrary SQL and pivot to shell. Horizon3 and SRA Labs published technical details; Help Net Security and The Hacker News confirm honeypot exploitation from 2026-08-30 by a single IP dropping reverse shells and enumerating processes. Patched 2026-07-14 in **Switchvox SMB 8.4.0.2**; roughly 4,000 exposed devices on Shodan, mostly U.S. **CISA KEV added it 2026-09-02.** For a telecom-security practitioner: any customer PBX-on-a-VLAN with the admin web reachable is now a same-day target; hunt the `/pa` POST pattern in web-front logs and pull any PostgreSQL query strings that concatenate `PhoneIP`. [The Hacker News](https://thehackernews.com/2026/09/attackers-exploit-critical-switchvox.html) · [Help Net Security](https://www.helpnetsecurity.com/2026/09/02/exploitation-of-sangoma-switchvox-flaw-underway-cve-2026-9586/) · [Horizon3 disclosure](https://horizon3.ai/attack-research/disclosures/cve-2026-9586-sangoma-switchvox-rce/) · [SRA Labs advisory](https://labs.sra.io/posts/switchvox/) · [IONIX](https://www.ionix.io/threat-center/cve-2026-9586/) · [SC World](https://www.scworld.com/brief/critical-sql-injection-vulnerability-in-sangoma-switchvox-exploited-in-the-wild) — 2026-09-02 (KEV addition); exploitation from 2026-08-30
- **Cisco Desk Phone 9800 / IP Phone 7800 / IP Phone 8800 / Video Phone 8875 with SIP software — unauth arbitrary file write + info disclosure.** [NOTABLE] Multiple directory-permissions vulnerabilities in the SIP-software builds of these phones let an unauthenticated remote attacker do arbitrary file write and information disclosure. Exploitation requires **Web Access** to be enabled on the phone; Web Access is off by default, which materially cuts the fleet-wide blast radius. No workarounds — fixed software only. Practitioner impact: many enterprise phone deployments turn Web Access on for provisioning or debug and forget it — do a fleet-wide check of the `Web Access` toggle before assuming default-off saves you. [Cisco advisory (cisco-sa-phone-write-g3kcC5Df)](https://sec.cloudapps.cisco.com/security/center/content/CiscoSecurityAdvisory/cisco-sa-phone-write-g3kcC5Df) · [Cyber Security News](https://cybersecuritynews.com/cisco-desk-ip-and-video-phone-vulnerabilities/) · [GBHackers](https://gbhackers.com/cisco-desk-phone-series-vulnerability/) · [CyberPress](https://cyberpress.org/cisco-desk-ip-and-video-phones-vulnerable/) — 2026-09-02

## General high-severity

- **SonicWall SMA1000 zero-day chain — CVE-2026-83548 (CVSS 10.0, pre-auth SSRF) + CVE-2026-83549 (CVSS 7.8, post-auth OS command injection); hotfix and disclosure 2026-09-02, active exploitation confirmed, on CISA KEV.** [CRITICAL] CVE-2026-83548 is a pre-auth SSRF in the SMA1000 Appliance Work Place interface that lets an unauthenticated remote attacker reach sensitive functionality; CVE-2026-83549 is a post-auth OS-command injection in the Appliance Management Console (AMC) exploitable under specific conditions to run arbitrary OS commands. Chained end-to-end, the pair gives unauthenticated remote code execution on internet-exposed SMA1000 6210 / 7210 / 8200v. Attackers are deploying a custom toolkit — **ROOTRUN** (setuid ELF binary providing persistent root execution), **KNUCKLEBALL** (Python loader that injects into the appliance's own JVM), and **ORANGETAIL** (custom Java web shell) — and INC Ransomware is the dominant post-exploitation actor. This is the third distinct SMA1000 zero-day campaign in under a calendar year (Dec-2025 CVE-2025-40602 AMC chain; June/July-2026 CVE-2026-15409/15410 with theft of TOTP MFA seeds; now 83548/83549). **Patch to 12.4.3-03526 or 12.5.0-02952** and treat any SMA1000 that faced the internet before patching as compromised — the July MFA-seed theft means simply patching does not restore integrity of second factors issued from stolen seeds. [Sophos (primary telemetry)](https://www.sophos.com/en-us/blog/sonicwall-83548-83549) · [The Hacker News](https://thehackernews.com/2026/09/attackers-exploit-two-sonicwall-sma.html) · [BleepingComputer](https://www.bleepingcomputer.com/news/security/sonicwall-warns-of-actively-exploited-sma1000-zero-day-flaws/) · [Help Net Security](https://www.helpnetsecurity.com/2026/09/02/sonicwall-sma-1000-cve-2026-83548-cve-2026-83549-zero-day-attacks/) · [Infosecurity](https://www.infosecurity-magazine.com/news/hackers-chain-sonicwall-zeroday/) · [Cyber Security News](https://cybersecuritynews.com/sonicwall-remote-code-execution-vulnerabilities/) · [SonicWall SMA 1000 hotfix KB](https://www.sonicwall.com/support/knowledge-base/kA1VN0000000Ky70AE) · [ComplianceHub retrospective](https://compliancehub.wiki/inc-ransomware-sonicwall-sma1000-mfa-seed-theft-kev-2026/) — 2026-09-02

- **AI-gateway exploitation cluster — LiteLLM, Starlette, Kestra, RAGFlow — now KEV-mandatory.** [HIGH] Microsoft's 2026-08-26 blog first assessed with high confidence that attackers were chaining **CVE-2026-42271** (authenticated command execution in LiteLLM MCP `stdio` test endpoints) with **CVE-2026-48710** (Starlette host-header validation bypass) to convert an authenticated primitive into unauthenticated RCE against LiteLLM gateways, alongside independent exploitation of **CVE-2026-49869** in Kestra (auth-bypass permitting an unauthenticated attacker to create and run a malicious workflow — direct shell execution) and payload delivery through RAGFlow. Post-exploitation goals observed: steal model-provider API keys (OpenAI, Anthropic, Azure OpenAI etc.), establish persistence on the gateway host, reach backend data stores, and deploy cryptominers. CISA's 2026-09-02 KEV addition of **CVE-2026-48710**, **CVE-2026-49869** and **CVE-2026-59822** (BerriAI LiteLLM improper authentication) makes these federally compulsory to patch. Practitioner impact: any AI-agent pilot inside an enterprise that fronts to LiteLLM / Kestra / RAGFlow is currently on the exploited-in-the-wild list; rotate model-provider credentials on any host that was exposed to the internal network, not just those facing the internet.
