## Telecom

- **Citrix NetScaler ADC / NetScaler Gateway — CVE-2026-88771 (CVSS v4 9.5) and CVE-2026-88772 (CVSS v4 9.5), Citrix bulletin CTX697096 published 2026-09-27, both actively exploited zero-days, added to CISA KEV 2026-09-27; direct telco relevance.** CVE-2026-88771 is an **unauthenticated improper-input-validation** flaw in the NetScaler management plane that lets a remote attacker run arbitrary OS commands on the appliance. Citrix's own advisory language emphasises that the flaw affects **every ADC / Gateway on an affected build in its default configuration — no special feature (VPN vserver, AAA, ICA proxy, load balancer, gateway virtual server) has to be enabled** — which is the same "always-on, always-reachable" property that made CitrixBleed (CVE-2023-4966) and the 2024 NetScaler RCEs so devastating at telco perimeters. CVE-2026-88772 is a memory overflow reachable when **DTLS** is enabled; because NetScaler ADC turns DTLS on by default for VPN virtual servers, the practical exposure surface for a large operator is broad. watchTowr said it observed exploitation of both on **unmitigated** deployments during forensic investigations and issued a Rapid Reaction to clients on 2026-09-26 before CVE IDs had been assigned — i.e. the exploitation predates the fix. **Fixed builds:** NetScaler ADC / Gateway 14.1-73.37 or later; 13.1-64.23 or later; NetScaler ADC 14.1-73.37 FIPS; 13.1-37.279 for the 13.1-FIPS and 13.1-NDcPP editions. Bulletin CTX697096 also contains six further CVEs — most notably CVE-2026-88773 (HTTP Request Smuggling, CVSS v4 9.3) and a set of memory-overflow issues rated 7.0–8.8. **Telecom relevance:** NetScaler ADC / Gateway is the load-balancer / VPN / application-delivery front-door of choice at most large operators and telecom-focused MSPs. Typical telco NetScaler footprints: (i) employee remote-access Gateway with SAML/AAA into workforce IDP, (ii) L7 load balancer in front of BSS / OSS / CRM (customer self-service, MVNO management, order handling), (iii) partner / dealer / channel extranet fronting SOAP/REST APIs into fulfilment, (iv) reverse-proxy for CAMARA / Open Gateway northbound and B2B interconnect microsites, (v) Citrix VDI Gateway in operations centres and NOC / SOC estates. An unauth OS-command primitive on an appliance in any of those positions gives an attacker a persistent north-of-firewall foothold that has historically been used by Chinese-nexus operators to pivot into carrier subscriber-facing systems (Salt Typhoon 2024 pattern). **Priority action for a carrier / MSP fleet:** enumerate all NetScaler management IPs and Gateway virtual-server IPs (Shadowserver-scale exposure is measured in the tens of thousands globally; carriers usually run several dozen), snapshot config, patch to the exact builds above (a NOT-later-than build 14.1-73.37 / 13.1-64.23), rotate any credentials or keys stored on the appliance (including LDAP/AD bind, RADIUS shared secrets, SAML signing keys, session-cookie AES keys), search web / kernel / syslogs for suspicious `sh`/`bash` execs from the management-plane processes, and pull memory / crash dumps for retroactive triage — watchTowr's forensic finding implies the earliest exploitation predates public awareness by an unknown period. - **Kyverno CVE-2026-100706 (CVSS 9.9) — published 2026-09-27 inside window.** Kyverno < 1.19.1 fails to properly validate URL-encoded path segments in Policy `apiCall.urlPath`, so a namespace tenant can bypass the per-namespace clamp and create objects in other namespaces **as the admission-controller ServiceAccount**. Percent-encoded directory-traversal sequences reach both cluster-wide `MutatingWebhookConfiguration` objects (which become a persistent inject-anything primitive on every future admission decision) and `PolicyException` objects in the `kyverno` namespace (which whitelist further tenant escapes) — either route completes namespace-tenant → cluster-admin. Fixed in Kyverno 1.19.1. **Practitioner view:** Kyverno is a common policy engine in operator container platforms (5G NFs on-cluster, OSS/CRM microservice estates, edge-K8s at MEC sites); a namespace-tenant escape into cluster-admin is the classic multi-tenant-K8s worst case. Sweep operator clusters for Kyverno < 1.19.1, especially anywhere multiple app teams share a control plane.
