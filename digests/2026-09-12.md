**Adjacent, worth naming here rather than in "General":**

**GitLab CVE-2026-85706 (CVSS 10.0) — CISA KEV, 2026-09-11 — telco-adjacent because self-managed GitLab is common for RAN/core/OSS-BSS engineering.** Any operator or vendor running self-hosted GitLab CE/EE for internal RAN feature work, 5G core config, BSS integration or CI/CD needs to treat this as an urgent inventory question. An unauthenticated attacker can send one HTTP POST to the repository-commits API with a crafted `file.path` and read arbitrary files off the GitLab host — `.env`, `config/secrets.yml`, deploy keys, log files, runner tokens. Any of those leaks a way onto the network the GitLab instance is trusted from, which in a telco context often includes access to build systems that reach lab and pre-production RAN/core testbeds. Fixed in 19.3.2, 19.2.6, 19.1.8 (2026-09-10). Detection: log HTTP POSTs to `/api/v4/projects/[id]/repository/commits/` containing a `file.path` parameter (watchTowr detection guidance). Sources: [BleepingComputer](https://www.bleepingcomputer.com/news/security/gitlab-urges-users-to-patch-max-severity-path-traversal-flaw/), [SecurityWeek](https://www.securityweek.com/gitlab-vulnerability-exploited-one-day-after-disclosure/), [The Hacker News](https://thehackernews.com/2026/09/gitlab-cvss-10-file-read-flaw-draws-in.html), [watchTowr rapid reaction](https://watchtowr.com/resources/rapid-reaction-gitlab-critical-path-traversal-vulnerability-cve-2026-85706/), [Horizon3 analysis](https://horizon3.ai/attack-research/vulnerabilities/cve-2026-85706/), [GitLab release notes](https://docs.gitlab.com/releases/patches/patch-release-gitlab-19-3-2-released/), [Field Effect](https://fieldeffect.com/blog/gitlab-fixes-critical-vulnerability-probing-begins), [CISA KEV alert page](https://www.cisa.gov/news-events/alerts/2026/09/11/cisa-adds-one-known-exploited-vulnerability-catalog). Date KEV: 2026-09-11. **CRITICAL**.
