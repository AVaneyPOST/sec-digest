## Telecom

- **CISA KEV: Linux kernel kTLS receive-path flaw actively exploited (2026-09-18).** CVE-2025-39682 — improper check for exceptional conditions in the kernel TLS receive path lets a zero-length record from the `rx_list` bypass `recvmsg()` record-type handling, poisoning subsequent TLS records with wrong zero-copy / queuing assumptions. CVSS 9.8. Remotely triggerable given a TLS-terminating socket. **Telco relevance:** kTLS is on the hot path anywhere a Linux box terminates HTTPS/gRPC/DoT/DoH at line rate — 5G SBI (N32-c/N32-f fronts, NRF, SMF, AMF), IMS media gateways, DPI/CGNAT with L7 offload, plus TLS-fronted OAM. A remote crash primitive here reaches into signalling infrastructure that operators historically assume is out of reach. Federal patch deadline 2026-09-21. [CISA (one KEV add)](https://www.cisa.gov/news-events/alerts/2026/09/18/cisa-adds-one-known-exploited-vulnerability-catalog) · [Windows Forum brief](https://windowsforum.com/news/cve-2025-39682-in-kev-patch-linux-ktls-before-sept-21.445003/) · [CVE Security summary](https://cve-security.com/cve/cve-2025-39682) — 2026-09-18 — **CRITICAL**.
- **CISA KEV: Linux kernel AF_ALG crypto race + ebtables SNAT OOB (2026-09-18).** CVE-2025-39964 — race condition in the AF_ALG datapath (two writers per socket interleaving request payloads → corrupted crypto results / DoS). CVE-2026-53266 — netfilter bridge `ebtables` SNAT target out-of-bounds write, local privilege escalation. **Telco relevance:** AF_ALG is common in appliance crypto engines (IPsec offload, TLS acceleration on user-plane gateways); the ebtables SNAT path is used in edge/UPF bridged deployments where BSS/OSS containers share a Linux bridge. Both KEV entries carry the Sept 21 federal remediation deadline. ## General high-severity

- **Check Point CVE-2026-91843 — unauth root RCE on Management/Log/Multi-Domain servers (Sept 16 disclosure, Sept 18 updates).** Stack overflow in the login path: an overlong username received before authentication overflows and delivers root code execution on the management plane. CVSS 9.8. Affects R82.20, standalones, Log Servers and Multi-Domain servers; fixed via LivePatch (sk1000155). Check Point reports no in-the-wild exploitation; CISA's Sept 17 CVE assessment recorded exploitation status as "none". This is the fifth pre-auth critical on Check Point's management plane since July 22 — pattern suggests a family of bugs, not a single mis-step. ## Worth watching

- **Cisco ISE PoC exposure**. History says a public PoC lands within a week of a CVSS-10 unauth ISE disclosure; that clock started Sept 16. Anyone with ISE reachable outside OAM should stop assuming a rate-limited internet is buying them time.
- **Check Point management-plane pattern**. Five pre-auth criticals on the same surface in two months implies an unfinished audit. Assume more come — inventory Security Management / Log Servers now, restrict `Trusted Clients` per the Sept 18 mitigation, and be ready to redeploy R82.20 quickly.
- **vm2 in RCS/messaging enrichment / VAS platforms**. If your MMS/RCS pipeline or a customer-facing script surface uses vm2 (or another Node.js sandbox lib with similar apply-trap plumbing), pull the version numbers now. This class of escape often generalises quickly across libraries.
- **Linux kernel kTLS in 5G SBI**. CVE-2025-39682 is the first widely-exploited flaw specifically in the kernel TLS receive path in a while. Research pieces detailing chained exploitation (crash → recovery → downgrade in a control-plane peering) are the ones to watch.
- **AI-driven vishing at carrier fraud teams**. Mandiant putting vishing at #2 initial access, paired with the AI orchestration angle, is a signal to carrier fraud analytics to retune call-centre models for scale, not just call quality — expect a rise in high-fidelity impersonation calls targeting number-port and eSIM issuance flows in the next quarter.
- **Salt Typhoon oversight**. No fresh disclosure in the 24h window. Persistent backdrop; carriers should not treat "evicted" as "removed" without ongoing telemetry.
