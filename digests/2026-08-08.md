# Security digest — 2026-08-08

Window: 2026-08-07 04:06 UTC → 2026-08-08 04:06 UTC. Black Hat USA / DEF CON week
is the dominant backdrop — most of the fresh disclosures below dropped from stage

## TL;DR

- **SCTPhantom (CVE-2026-64564)** — 18-year-old use-after-free in the Linux SCTP
  ASCONF path. Local root and container escape. Relevant to any SIGTRAN /
  Diameter / M3UA stack that terminates SCTP on Linux (STP, DEA, MME, PGW, PCRF,
  IMS S-CSCF). Patched kernels 6.6.148 / 6.12.101 / 6.18.42 / 7.1.6.
- **Zapscape (CVE-2026-64561)** — public PoC KVM guest-to-host escape via shadow
  MMU UAF. Requires guest root; every mobile core running on virtualised Linux
  infra is in scope.
- **N-central CVE-2026-18577** — still being cleaned up: N-able confirms attackers
  are taking over N-central servers after the initial fix was incomplete. CISA
  KEV-listed. MSP-blast-radius risk.
- **Interrupt Injection / "TONTOU" (CVE-2026-68480)** — MIT bypass of Spectre v2
  mitigations on AMD Zen 2 (extraction of `/etc/shadow` demonstrated). Kernel
  patches shipped in 6.18.43 / 6.6.149 / 6.1.181.
- **AI coding-agent RCE chain** — Black Hat demo: a single unauthenticated GitHub
  issue reaches CI runners on Claude Code (CVE-2026-54316), Gemini CLI
  (CVE-2026-12537, CVSS 10.0), and OpenAI Codex-style multi-stage workflows.
- **Unlimited Technology Systems** — 3.8M-person US healthcare data breach
  disclosed. Now the largest HHS-reported healthcare breach of 2026 to date.

## Telecom

- **SCTPhantom — Linux SCTP ASCONF UAF (CVE-2026-64564)** — Tencent Zhuque Lab
  published details on 06 Aug; kernel CVE team formally assigned on 04 Aug.
  Root cause is a stale cached-pointer race in DEL-IP handling that dates back
  to 2.6.25 (2007). Local privilege escalation and container escape confirmed on
  Debian 13, Ubuntu 24.04, RHEL 9, Rocky 9, and OpenCloudOS. Exposure requires
  SCTP reachable on the target — which is precisely the profile of signalling
  gateways (SIGTRAN M3UA/SUA/M2PA, Diameter over SCTP, XCAP over SCTP in some
  IMS deployments). Any telco Linux host that terminates SCTP for interconnect
  or intra-core needs the kernel bumped now; do not wait for the vendor image
  refresh. [Tencent Zhuque Lab writeup](https://matrix.tencent.com/en/2026/08/06/sctphantom-CVE-2026-64564)
  · [oss-security thread](https://www.openwall.com/lists/oss-security/2026/08/06/13)
  · [The Hacker News](https://thehackernews.com/2026/08/18-year-old-linux-sctp-flaw-could-let.html)
  · 2026-08-06 · [CRITICAL]

- **N-able N-central CVE-2026-18577 — active exploitation continues** — 07 Aug
  intelligence briefings and Rapid7's ETR confirm ongoing exploitation of the
  incomplete-patch authentication bypass. N-able is now telling customers that
  attackers achieved full admin takeover of N-central servers after the initial
  fix for CVE-2026-18556 proved insufficient. Not a signalling issue, but
  N-central is heavily deployed inside telco MSP / managed-services fabrics
  (small/regional operators, wholesale carriers) and its Take Control feature
  gives lateral pivots into managed endpoints. If your operator or a supplier
  runs N-central, treat as compromise until proven otherwise; hotfix landed
  02 Aug and CISA KEV added it 04 Aug.
  [Rapid7 ETR](https://www.rapid7.com/blog/post/etr-cve-2026-18577-n-able-n-central-authentication-bypass-exploited-in-the-wild/)
  · [S-RM briefing 07 Aug](https://www.s-rminform.com/cyber-intelligence-briefing/n-central-users-urged-to-patch-actively-exploited-vulnerability-7-aug-2026)
  · [The Hacker News](https://thehackernews.com/2026/08/n-able-says-attackers-take-over-n.html)
  · 2026-08-07 · [HIGH]

- **Zapscape — KVM guest→host escape (CVE-2026-64561)** — public PoC dropped
  06 Aug by Hyunwoo Kim (@v4bel). Shadow-MMU use-after-free in the recursive
  zap path; guest root inside an L1 VM can execute code on the Linux host.
  Intel needs both 4-level and 5-level EPT exposed to the guest; AMD is
  unconditional. No confirmed in-the-wild use yet. Directly relevant to any
  virtualised 5G SBA / NFV / MEC deployment — CNF-based cores, MANO stacks
  running KVM, and every telco private cloud (OpenStack, OpenShift-Virt,
  Kubevirt) that shares a KVM hypervisor between tenants is potentially
  broken until the fix (commit 2abd5287f083) is picked up.
  [The Hacker News](https://thehackernews.com/2026/08/new-zapscape-kvm-flaw-could-let.html)
  · [SecurityOnline](https://securityonline.info/kvm-escape-vulnerability-zapscape/)
  · [Cybersecurity News](https://cybersecuritynews.com/zapscape-kvm-escape-root-privileges/)
  · 2026-08-06 · [HIGH]

## General high-severity

- **AI coding-agent RCE — Claude Code / Gemini CLI / OpenAI Codex** — Novee
  Security presented at Black Hat USA (talk 05 Aug, coverage rolling 06-07 Aug).
  A GitHub issue opened by an account with no repo privileges is enough to
  execute code on the CI runners behind the vendor coding-agent workflows and,
  for OpenAI, to hijack the next agent run. Specifics: Claude Code shell-quoting
  bypass and a second read-only `tac` bypass used to exfiltrate an API key
  through GitHub Actions logs (CVE-2026-54316); Gemini CLI OS command injection
  via a crafted `.gemini/.env` in the container launcher (CVE-2026-12537,
  CVSS 10.0); Codex/AGENTS.md as a persistent attacker-controlled prompt
  surface across workflow stages. If you run any agentic CI on public repos,
  audit token scopes on PR jobs today.
  [eSecurity Planet](https://www.esecurityplanet.com/threats/black-hat-2026-critical-flaws-found-in-anthropic-google-and-openai-coding-agents/)
  · [The Hacker News](https://thehackernews.com/2026/08/claude-code-and-gemini-cli-flaws-let.html)
  · [Novee](https://novee.security/blog/critical-flaws-in-anthropic-google-and-openais-coding-agents/)
  · 2026-08-05..07 · [HIGH]

- **Interrupt Injection / TONTOU (CVE-2026-68480) — Spectre v2 bypass** — MIT
  CSAIL (Trujillo, Yan) presented at Black Hat 06 Aug; USENIX Security paper
  due next week. The technique closes a time-of-neutralization → time-of-use
  window in existing Spectre v2 defences. Demonstration on AMD Zen 2 running
  Linux 6.14 with all default mitigations on: 5.47 B/s kernel-memory leak at
  ~92% accuracy, enough to locate and read `/etc/shadow` in 5/10 runs. Linux
  stable 6.18.43 / 6.6.149 / 6.1.181 landed the mitigation; AMD advisory
  AMD-SB-7018 tracks it. Practical impact on multi-tenant hosts (cloud, VDI,
  shared CI) is the concern; single-tenant boxes are less pressing.
  [The Hacker News](https://thehackernews.com/2026/08/new-interrupt-injection-attack-can.html)
  · [Privacy Guides](https://www.privacyguides.org/news/2026/08/07/spectre-is-back-cpu-mitigations-found-to-be-ineffective/)
  · [AMD-SB-7018](https://www.amd.com/en/resources/product-security/bulletin/amd-sb-7018.html)
