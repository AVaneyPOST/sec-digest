## TL;DR
- **Adobe finally shipped StyleSmuggler — APSB26-146, CVE-2026-75650, CVSS 10.0, published 2026-09-07 20:20 UTC.** The three-day zero-day carry-forward is resolved: Adobe assigned a CVE, rated it Priority 1 (highest) and shipped a composer hotfix (`VULN-39341-composer-patches.zip` off `repo.magento.com`). Any storefront that carried the July/August 2026 patches is still exploitable and, per Sansec's original disclosure, has to be assumed pre-compromised — patch + backdoor sweep, not patch alone.
- **N-able N-central CVE-2026-86218 confirmed exploited in the wild — pre-auth RCE, CVSS 10.0.** N-able's private customer notice (surfaced publicly by Help Net Security 2026-09-07) says the flaw "has been observed being exploited in the wild"; public release-notes still hedge to "no confirmations." Scans originating from `23.234.64.0/18`; attacker TTPs include appending `.invalid` (or similar odd strings) to known N-able administrator email addresses to create accounts, and probing an internal recon endpoint. MSP tenants hosting the N-central appliance are the blast radius; treat any unpatched instance as compromise-candidate.
- **ConnectWise ScreenConnect — worm-like campaign confirmed, still no CVE, still no patch.** Huntress and Help Net Security (2026-09-07) tie three unrelated intrusions (Quick Assist scam / phishing MSI / fake Geek Squad refund lure) into a single four-stage VBScript chain (`1.vbs` → `4.vbs`) that installs a rogue ScreenConnect client, then abuses the guest-file-transfer feature to push the same VBScript payload to newly-connected endpoints, giving worm-like propagation. ConnectWise advisory (2026-09-03) still says "CVE and patched release expected within the week"; five days in, that window is closing. Mitigation is to disable `TransferFiles` (legacy: `TransferFilesInSession`) on all technician roles until the fix ships.

GSMA T-ISAC, 3GPP SA3, and Ericsson / Nokia / Mavenir / Oracle Comms PSIRT feeds all quiet on Sunday-to-Monday cadence. MikroTrick, Sangoma Switchvox, Cisco IOS XR hardening bundle and Nexus 9000 Silicon One RCE remain the live operator-adjacent items — all carry-forward, no new operational tempo.

Active mass exploitation continues from `82.192.72.4` (since 2026-09-02); IoC on the host is a rogue user `0` creating an `ops` account (log line contains `ssh:-2@`). ~300k reachable-vulnerable devices per Shodan. Telco relevance unchanged: MikroTik CCR / CRS / hEX sit inside WISP subscriber-edge, MVNE bespoke aggregation, small-cell / DAS transport, private-LTE/-5G perimeter and mid-market MPLS-CE fleets — any operator audit that scoped-out vendor-managed edge routers needs a rescope. Not KEV-listed at end of in-window (six days now); expected 2026-09-08 or 2026-09-09 KEV cycle. ## General high-severity

- **Adobe Commerce / Magento StyleSmuggler patched — CVE-2026-75650 (CVSS 10.0), APSB26-146, Priority 1, published 2026-09-07 20:20 UTC.** [CRITICAL] Three-day zero-day carry-forward resolved. Adobe published the emergency composer hotfix (`VULN-39341-composer-patches.zip` on `repo.magento.com`) inside the scheduled 2026-09-08 release window. The bulletin explicitly says Adobe is aware of CVE-2026-75650 being exploited in the wild. Affected: every Magento Open Source and Adobe Commerce build from 2.4.4 through 2.4.9, and Adobe Commerce B2B 1.3.3–1.5.3. Root cause is a two-stage template-injection via Magento's styles-properties path — injected style attributes reach the template system and get rendered as PHP → unauth RCE and persistent backdoor plant. Sansec's original disclosure (2026-09-05) put ITW start no later than 2026-09-04. Practitioner action: apply the hotfix (composer patch, not a full release), then run a compromise-assessment sweep on `pub/`, `app/design/`, `var/view_preprocessed/` and email-template blobs — the backdoor drops in template-side artefacts, not obvious `.php` shells. WAF virtual-patch rules for the affected endpoints stay useful until the hotfix has propagated.
