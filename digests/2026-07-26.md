## TL;DR

- **Fastjson 1.x CVE-2026-16723 — active exploitation in the wild against Spring Boot apps, and there is still no fixed 1.x release.** ThreatBook and Imperva confirmed on 25 Jul that attackers are already hitting financial services, healthcare, computing, and retail targets (primarily US, some Singapore/Canada). The chain works against Fastjson 1.2.68–1.2.83 in default configuration — AutoType stays off, no classpath gadget needed — and Alibaba lists the 1.x branch as end-of-life with migration to Fastjson2 as the only long-term fix. Interim mitigation is `-Dfastjson.parser.safeMode=true` or the `1.2.83_noneautotype` build. This is a "patch doesn't exist, only workarounds" event on a library that shipped inside a very large amount of Java infrastructure.
- **SourTrade — malvertising campaign that makes the victim's browser assemble the final Windows executable in memory.** Confiant's write-up hit the press cycle on 25 Jul (BleepingComputer, The Hacker News). The landing pages impersonate TradingView, Solana and Luno, cloak researchers/scanners with blank pages, and use ServiceWorker + SharedWorker + AES-CTR to build a Bun-runtime-based payload from ad-served bytes in-browser — defeating hash-based detection by construction. Live since late 2024, 25 languages, 12 countries, primarily APAC/LATAM/Africa/Australia/UK, retail traders and crypto investors. The interesting artefact is the delivery model: file-fingerprinting-based defences never see a static payload to fingerprint.
- **ShinyHunters-leaked emails now feeding a $2,000 Bitcoin sextortion wave.** BleepingComputer on 25 Jul: operators are trawling the ShinyHunters dumps (Amtrak, Hallmark, Substack, Betterment, CarGurus, ADT, Panera Bread, McGraw Hill) and using the exposed addresses to make sextortion "we compromised your device" messages look targeted. Not the extortion group itself — a downstream reuse. Consumer-scale, but relevant to abuse desks and to the operational read that ShinyHunters leaks now have long-tail secondary abuse patterns.
- **GitLab self-managed 18.11.3 — public PoC lets any authenticated pusher run commands as `git`, no CVE, no security-advisory treatment from GitLab.** Yuhang Wu / depthfirst's write-up landed in the 24-25 Jul press wave. The chain is a Jupyter-notebook commit + diff request that leaks a heap pointer, followed by two crafted notebooks that fire the payload. Fixed in 18.10.8 / 18.11.5 / 19.0.2 (10 Jun) via an Oj gem bump listed under bug fixes, not security fixes. Meaningful because it undercuts the standard patch-triage signal (no CVE ⇒ not urgent) on a public RCE.

## General high-severity

- **CVE-2026-16723 — Fastjson 1.x RCE, in-the-wild exploitation confirmed, no patched 1.x version available.** The Hacker News published a follow-up on 25 Jul aggregating the ThreatBook and Imperva telemetry: exploitation has moved from PoC to production against Spring Boot deployments running Fastjson 1.2.68–1.2.83. The vulnerability was originally disclosed by FearsOff on 21 Jul with the maintainer's advisory the same day; the notable 25 Jul development is that (a) attackers are hitting real targets — financial services, healthcare, computing, retail — with the largest volumes against US organisations and smaller volumes against Singapore and Canada, and (b) Alibaba has still not shipped a fixed 1.x artefact and appears not to be planning to, with the 1.x branch marked end-of-life and migration to Fastjson2 the only long-term path. The default-configuration angle is what makes this ugly: AutoType can remain disabled, no classpath gadget is required, and any network-reachable JSON-parsing endpoint that hasn't enabled SafeMode is a candidate. Interim mitigations: `-Dfastjson.parser.safeMode=true`, or the `com.alibaba:fastjson:1.2.83_noneautotype` build. Practical read: this is a "you have to migrate" event for anyone still on the 1.x branch, and the migration cost is real — inventory dependency graphs now, not when the KEV addition forces the timeline. [The Hacker News](https://thehackernews.com/2026/07/fastjson-1x-rce-vulnerability-targeted.html), [Security Boulevard / Imperva](https://securityboulevard.com/2026/07/imperva-customers-protected-against-cve-2026-16723-critical-fastjson-1-x-zero-day-rce/), [Security Online (PoC)](https://securityonline.info/fastjson-rce-1-2-83/), [TheHackerWire CVE entry](https://www.thehackerwire.com/vulnerability/CVE-2026-16723/). Date: 2026-07-25 (in-wild exploitation confirmation and no-patch status). [CRITICAL]

- **SourTrade — malvertising campaign assembles per-victim Windows executable inside the browser, defeating file-fingerprinting by design.** Confiant's technical write-up dropped 23 Jul; BleepingComputer, The Hacker News and follow-on outlets picked it up in the 25 Jul press cycle. Landing pages impersonate TradingView, Solana and Luno, fingerprint each visitor and show researchers/scanners a blank page. Real visitors get a `ServiceWorker` that acts as a download manager, pulls a legitimate `Bun` runtime from separate infrastructure, generates additional bytes locally with AES-CTR inside a `SharedWorker`, and assembles the final binary in-memory before triggering a same-origin download. Because no single origin ever serves the complete executable, hash-based / signature-based static detection has nothing to catch. Active since late 2024, 25 languages, 12 countries — heaviest in APAC and LATAM, with additional activity in Africa, Australia and Great Britain. Retail traders and cryptocurrency investors are the target profile; ad ecosystems abused include Google, Meta/Facebook and X. Detection implication: browser-side EDR / DEM telemetry (unusual `ServiceWorker` registrations, `SharedWorker`-driven in-memory buffer assembly, Bun-runtime execution originating from freshly downloaded blobs) is now doing work that network-level file scanning cannot. [The Hacker News](https://thehackernews.com/2026/07/malvertising-sends-malware-in-pieces.html), [BleepingComputer](https://www.bleepingcomputer.com/news/security/malicious-sites-use-javascript-to-build-malware-in-browser-memory/), [Cyber Security News](https://cybersecuritynews.com/sourtrade-malvertising-malware/), [Confiant original](https://blog.confiant.com/p/sourtrade-browser-assembled-malware), [GBHackers](https://gbhackers.com/sourtrade-browser-assembled/). Date: 2026-07-25 (press wave; Confiant original 23 Jul). [HIGH]

- **ShinyHunters-leaked breach data now driving a $2,000 Bitcoin sextortion wave.** BleepingComputer, 25 Jul: unrelated scam operators are pulling the ShinyHunters public dumps and using the exposed email addresses to send sextortion mail claiming device compromise, keyboard/camera/microphone access, and captured "compromising videos", demanding $2,000 in Bitcoin within 48 hours. Data sources confirmed reused in the campaign: **Amtrak, Hallmark, Substack, Betterment, CarGurus, ADT, Panera Bread, McGraw Hill**. The messages are not from ShinyHunters — they're downstream reuse by scam operators — but the presence of the recipient's real address inside the message body raises the perceived credibility above the usual "sent to yourself" sextortion bar. Not a compromise event, but worth logging because (a) abuse desks at any of the reused-breach companies will see spike volumes, (b) email-security tuning should flag the pattern (`$2,000` + BTC + "48 hours" + reference to breach-source domains), and (c) any customer-facing security team should be ready with the "this is a scam, we did not send it" message. [BleepingComputer](https://www.bleepingcomputer.com/news/security/shinyhunters-data-leaks-fuel-2-000-sextortion-email-scam/). Date: 2026-07-25. [NOTABLE]

- **GitLab self-managed — public PoC executes commands as `git` for any authenticated pusher (18.11.3 unpatched); GitLab did not treat the underlying fix as a security fix.** Yuhang Wu at depthfirst published a working exploit on 24 Jul; The Hacker News / GuardianMSSP / follow-on outlets covered it into the 25 Jul cycle. The chain: an authenticated user commits a crafted Jupyter notebook, opens its commit diff — which leaks a heap pointer via an `Oj` gem bug — repeats to locate library base addresses, then commits two more notebooks whose diffs fire the payload. No admin rights, no CI/runner access, no other-user interaction required. Affected: CE/EE 15.2.0–18.10.7, 18.11.0–18.11.4, 19.0.0–19.0.1; fixed in 18.10.8, 18.11.5 (10 Jun) and 19.0.2. Published `Oj` gem versions 3.13.0–3.17.1 vulnerable; 3.17.3 is the first release with both fixes. Notably: **no CVE, no CVSS, no mention of the notebook-diff chain in GitLab's release notes** — the `Oj` bump is listed under bug fixes, not the security-fix table. Read: the usual "no CVE ⇒ not urgent" signal is wrong on this one, and any self-managed GitLab estate still on 18.11.3 (or the other listed ranges) should treat it as an urgent patch. Practical hunt for still-unpatched instances: unusual push-plus-diff sequences of `.ipynb` files from low-privileged accounts, `git`-user shell activity that doesn't match legitimate runner or hook execution. [The Hacker News](https://thehackernews.com/2026/07/researcher-publishes-gitlab-rce-poc.html), [GuardianMSSP mirror (2026-07-25)](https://www.guardianmssp.com/2026/07/25/researcher-publishes-gitlab-rce-poc-letting-authenticated-users-run-commands-as-git/), [GitLab 18.11.5 release notes](https://docs.gitlab.com/releases/patches/patch-release-gitlab-19-0-2-released/). Date: 2026-07-24 (research) / 2026-07-25 (press wave). [HIGH]

## Worth watching

- **Fastjson 1.x — the timeline compression is the story.** From advisory (21 Jul) to public PoC (23 Jul) to confirmed in-wild exploitation across multiple sectors (25 Jul) took four days on a library that ships inside a large fraction of Java web-tier deployments. Anticipate KEV addition inside the week and plan the migration to Fastjson2 now rather than after the KEV clock starts. Compensating controls: WAF signatures for polymorphic JSON payloads with `@type` markers, egress restriction on the Spring Boot fleet, prompt-mode SafeMode enable across the estate. If you cannot migrate: catalogue every Spring Boot artefact with a Fastjson 1.x dependency (direct or transitive) and treat each as an internet-reachable-if-fronted-by-a-web-tier host.
- **SourTrade — browser-assembled malware is a pattern to expect more of.** The design choice — build the payload in-browser from bytes served across multiple origins — cleanly defeats the entire class of file-hash / signature-scanning detections that constitute the majority of ad-security defensive plumbing. Expect other threat actors to copy the pattern within weeks. Detection focus shifts to: (a) `ServiceWorker` registrations on unfamiliar/unsanctioned origins, (b) `SharedWorker` in-memory buffer assembly, (c) same-origin downloads that were assembled rather than fetched, (d) Bun-runtime execution originating from freshly-downloaded blobs on user workstations. Enterprise SASE / browser-isolation postures that assumed static-file scanning were sufficient need to revise.
- **GitLab: "no CVE" bugs in the patch table are the interesting ones.** Any self-managed GitLab on 18.11.3 (or 15.2.0–18.10.7 / 18.11.0–18.11.4 / 19.0.0–19.0.1) that hasn't taken the 10 Jun cumulative should be patched immediately. Longer term, this is a reminder that treating vendor-published CVE lists as the sole patch-triage signal misses classes of bugs — bumps of Ruby gems inside GitLab's `Gemfile.lock` can carry exploitable primitives that never get GitLab-branded advisories.
- **Oracle CPU July 2026 — Communications tranche still the practical telecom item this week.** The 21 Jul CPU (Rev 3 last-updated 23 Jul) shipped **168 patches for Oracle Communications, 122 remotely exploitable without authentication** — Session Border Controller (CVE-2026-2332, CVSS 9.1 via Jetty), Converged Application Server (CVE-2026-61223 / 61225), Diameter Signaling Router (LPE + libssh in the Automated Test Suite), 5G Core Policy / NSSF / NRF (Spring Framework CVEs), NEF (Tomcat + LibTIFF). Operators that batch monthly CPU patches for telecom infra should verify this one is actually landing, not waiting for the next cycle. [Oracle CPU July 2026](https://www.oracle.com/security-alerts/cpujul2026.html), [Tenable analysis](https://www.tenable.com/blog/oracle-july-2026-critical-patch-update-addresses-1235-cves).
