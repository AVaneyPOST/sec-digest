**Perforce Puppet Enterprise CVE-2026-115731 KEV addition — operator OSS/BSS config-management-plane relevance** · [HIGH]
In-window. CISA added CVE-2026-115731 (Perforce Puppet Enterprise, "Deserialization of Untrusted Data") to the KEV catalog on **2026-11-17T17:53:15Z** with due date **2026-12-01** (BOD 26-04, so the 14-day window is scoped to federal civilian internet-exposed and high-value systems; stakeholders assess their own asset exposure). CWE-502 + CWE-94; CVSS 9.4 Critical (per vendor advisory and OpenCVE enrichment; several aggregators initially mis-stated severity). **Flaw:** Puppet Server's report-processing code deserialises a rich-data type contained in a PUT'd report; a client with any CA-signed agent certificate can execute arbitrary code as the Puppet service user. If the CA autosigns requests without strong verification, an unauthenticated network attacker obtains a signed agent cert and chains to RCE. **Fix:** Puppet Enterprise **2023.8.13, 2025.12.1, 2026.0.1** (puppet-agent 8.22.2 or 9.1.3). Perforce advisory dated 2026-11-03; CISA adds it 14 days after public disclosure, behind a PoC that appeared ~2026-11-14/15. **Operator relevance**: Puppet Server is a management-plane root-equivalent across any Puppet-managed node — in telco estates this is typical for Oracle Linux / RHEL / Rocky farms under OSS/BSS, element managers, NFV/VNF infra-management hosts, bastion jumpboxes, and vendor-provisioning jumpboxes. An attacker who obtains a signed agent cert (or exploits an autosign-without-verification misconfiguration) pivots from the Puppet Server into every managed node. **Mitigation if immediate upgrade is not possible**: disable autosigning or require strong external verification before the CA signs CSRs; restrict Puppet-Server reachability to management VLAN only; audit `/etc/puppetlabs/puppetserver/ca` CRL + cert issuance logs for new or unexpected agent certs since late October; monitor for `/puppet/v3/report/` PUT requests from unexpected agents and unusual response-time patterns. Forensics: CISA marked `forensicTriage: No`, which means no BOD 26-04 forensics-triage package is required by default — but internal operator hunt should still look for new unexplained processes running under the Puppet service account around the exposure window.

## General high-severity

**CISA KEV adds CVE-2026-115731 Perforce Puppet Enterprise — first BOD 26-04 addition of this catalog batch** · [HIGH]
In-window. See Telecom section above. The headline for the general-security view: the Puppet Server RCE needs **only a valid agent certificate**, which almost every Puppet-managed node already has. In environments where Puppet CA autosigning is turned on without a strong verifier, exploitation is effectively network-remote-unauthenticated. The 14-day BOD 26-04 deadline (2026-12-01) is the shortest internal-tooling deadline CISA has set in a single-addition batch this quarter; the compressed window reflects CISA's assessment of exploitation prevalence, not just CVSS. Public PoC code appeared roughly 48–72 hours before the KEV addition, which is consistent with the "PoC-first, then exploitation observed across sensors, then KEV" cadence CISA has adopted post-BOD-26-04. **Compliance note**: BOD 26-04 scopes patching to internet-exposed and high-value assets by default; for Puppet Server that scope is almost always the full fleet, because the Puppet Server is itself a HVA. Operators should treat 2026-12-01 as a hard internal deadline regardless of asset classification.
