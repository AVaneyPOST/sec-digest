## Telecom

**Unisoc VoLTE video-call → modem RCE → full Android kernel access — no CVE, no fix, no vendor response** — [The Hacker News](https://thehackernews.com/2026/08/unisoc-volte-video-call-exploit-chain.html), [Dark Reading](https://www.darkreading.com/mobile-security/video-call-exploit-chains-two-flaws-unisoc-modems), [Infosecurity Magazine](https://www.infosecurity-magazine.com/news/unisoc-modem-flaw-rce-calls/), [SSD Secure Disclosure — T612 LPE](https://ssd-disclosure.com/unisoc-t612-lpe/), [SSD — T612 RCE (March 2026 stage 1)](https://ssd-disclosure.com/unisoc-t612-rce/) — 2026-08-17 — **CRITICAL**
Two-stage chain. Stage 1 (published March 2026): unauthenticated RCE inside the Unisoc modem firmware, triggered by a malformed SIP INVITE for a VoLTE video call that the target device auto-processes. Stage 2 (published 2026-08-17): a modem-to-AP privilege escalation classified as **CWE-1189 (Improper Isolation of Shared Resources on SoC)**. Once code executes in the modem, the exploit writes a full-access configuration to the modem's ARM MPU via coprocessor registers, mapping the **entire 32-bit physical address space RWX from modem context — including the pages that hold the Android kernel**. Net result: an answered call yields kernel-level control of the handset.
**Affected chipsets:** Unisoc T606, T612, T7250 (modem firmware is shared). **Confirmed vulnerable devices** at time of publication: Motorola E13 (Feb 2025 patch level), Realme C33, Xiaomi Redmi A5 (**Jan 2026 patch level — current**). **Attack prerequisites:** attacker-controlled VoLTE infrastructure (rogue IMS/EPC — private 4G, IMSI-catcher w/ SIP core, or hostile IPX/roaming interconnect) and a user who answers the incoming video call. **Vendor response:** SSD says it tried email and LinkedIn; Unisoc did not respond. **No CVE assigned.**
For a telecom red-teamer this is unusually clean: the attack surface is already reachable from the S6a/S8/N32/IPX side (deliver a spoofed video-INVITE via a compromised P-CSCF or hostile visited network), and the payoff is Android root on hundreds of millions of low-end handsets across EMEA/APAC/LATAM. Enterprise BYOD fleets that permit budget Unisoc-based Androids should treat this as an unpatched RCE on unmanaged endpoints. Detection: log P-CSCF-side unusual SIP INVITE video sessions from unfamiliar user agents; interconnect-side, expect this to show up as fragmented SIP over Diameter Rx/N7 anomalies before it manifests on the handset.

**Oracle Critical Security Patch Update — August 2026 — 13 Oracle Communications patches, 8 unauth-remote, max CVSS 9.8** — [Oracle CSPU August 2026](https://www.oracle.com/security-alerts/cspuaug2026.html), [Oracle CSPU August 2026 verbose risk matrices](https://www.oracle.com/security-alerts/cspuaug2026verbose.html) — 2026-08-18 (released today) — **HIGH**

Still no SBC, DSR, Policy Management, or IN Service Platform advisories in this cycle — SBC operators can defer the emergency window, but Assurance / UIM / ASAP shops should not: 8 of 13 are network-reachable unauth vectors. Adjacent product families with CVSS ≥ 9 in the same CPU worth watching for shared components: Fusion Middleware and Hyperion (both 10.0), Siebel CRM and Analytics (9.9), Essbase / Commerce / E-Business Suite (9.8). Pull the verbose risk matrix, cross-reference against your Oracle-Comms inventory, and prioritise the unauth-remote 9.8s.

## General high-severity

**SAP Commerce Cloud CVE-2026-58231 (CVSS 10.0, unauth RCE) — now under active exploitation, PoC public** — [The Hacker News](https://thehackernews.com/2026/08/sap-commerce-cloud-cve-2026-58231.html), [BleepingComputer](https://www.bleepingcomputer.com/news/security/max-severity-sap-commerce-cloud-flaw-now-targeted-in-attacks/), [Security Affairs](https://securityaffairs.com/197244/security/sap-commerce-cloud-cve-2026-58231-exploited-in-the-wild.html), [SecurityOnline](https://securityonline.info/sap-august-2026-patch-day/), [SocRadar](https://socradar.io/blog/sap-commerce-cloud-cve-2026-58231/) — press wave 2026-08-17 — **CRITICAL**
Improper-authorization flaw in the **Data Hub Adapter** extension of SAP Commerce Cloud (COM_CLOUD 2211 / 2211-JDK21). Unauthenticated attacker submits a specially crafted request to a default auth-client endpoint, achieves arbitrary code execution. **Timeline:** SAP patched Aug 11 (SAP Patch Day); Defused Cyber honeypots picked up scan/exploit attempts on **Aug 14** — three days after patch; **KEVIntel confirmed real attacks with a working PoC on Aug 15**; broader coverage wave lands Aug 17 with PoC now publicly circulating. **Not yet on CISA KEV** at time of writing — expect an addition within the week. Any internet-facing Commerce Cloud storefront running the Data Hub Adapter is a live target — patch or take it off the internet before end of day.

**CISA KEV — 1 addition (2026-08-17): CVE-2025-62593 Ray-Project Ray code injection** — [CISA alert](https://www.cisa.gov/news-events/alerts/2026/08/17/cisa-adds-one-known-exploited-vulnerability-catalog), [The Hacker News](https://thehackernews.com/2026/08/cisa-adds-exploited-n-able-n-central.html) (mixed coverage), [GitLab advisory DB](https://advisories.gitlab.com/pkg/pypi/ray/CVE-2025-62593/) — 2026-08-17 — **HIGH**
Ray's browser defense checks that the User-Agent starts with "Mozilla"; combined with a DNS-rebinding attack against the developer's browser, that check is bypassed and code executes on the Ray host. Trigger: a developer running Ray locally (or on a reachable dashboard) is served a malicious ad or visits a malicious page. Patched in Ray **2.52.0**. **BOD 26-04 due date: 2026-08-20.** For anyone running ML dev infra, this is a lateral-movement primitive — Ray hosts often carry model artefacts, cloud creds, and cluster-admin tokens.
