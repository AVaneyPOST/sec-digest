## General high-severity

**SonicWall SonicOS SSLVPN — CVE-2026-19868 — KEV entry, no SonicWall bulletin yet**
The newest addition to CISA KEV is CVE-2026-19868, dateAdded 2026-11-06, dueDate 2026-11-20. The catalog description: single-factor authentication flaw that lets users with alternate-method credentials bypass SAML controls, including MFA. In effect this drops MFA on affected SonicOS SSLVPN deployments where an "alternate authentication method" is configured for a given user — a long-standing SonicOS pattern where SAML is wired up alongside a password/OTP fallback. KnownRansomwareCampaignUse is listed as Unknown; no public exploitation details and no SonicWall PSIRT SNWLID bulletin pinnable to the ID were indexed in-window. Immediate operator actions: audit SSLVPN user-portal configuration for any user/group with "allow fallback to local" or similar alternate-method flags, and disable fallbacks for any SAML-enforced population pending a SonicWall advisory. Not to be confused with CVE-2026-4116 / CVE-2026-4114 (April 2026 SMA1000 TOTP bypasses) or CVE-2024-12802 (May 2026 Gen6 SSL-VPN UPN LDAP MFA bypass) — different products, different mechanisms.
[source](https://raw.githubusercontent.com/cisagov/kev-data/main/known_exploited_vulnerabilities.json) · Date: 2026-11-06 (KEV), in-window exposure · [HIGH]

**WordPress Core — CVE-2026-119977 — active mass exploitation, CISA deadline past**
Confirmed exploitation. CWE-367 time-of-check / time-of-use race in the Core full-package upgrade mechanism: predictable, web-accessible staging paths let an unauthenticated attacker win the race and drop attacker-controlled code that the upgrade flow executes. CVSS 3.1 of 8.1 (attack complexity high because of the timing constraint, but in practice automatable against newly-upgrading installs). Affected: WordPress Core 4.7.0 through 7.1.3 — essentially everyone on Core who hadn't yet updated. Fixed in **7.1.4** (released 2026-10-28); backported fixes for eligible older branches. KEV dateAdded 2026-11-03, dueDate 2026-11-06 (now past). Wordfence reported **13,095 attack attempts in the preceding 24 hours** as of in-window roundups; probing began within hours of patch release. Any WordPress site that was mid-upgrade or on an unpatched Core during the past two weeks should be treated as potentially compromised: look for unexpected PHP files under `wp-content/upgrade/` and `wp-content/uploads/`, new admin users, and modified `wp-config.php`.
[source](https://socprime.com/?p=57139) · [source](https://www.bleepingcomputer.com/news/security/cisa-flags-wordpress-rce-flaw-as-actively-exploited-in-attacks/) · Date: 2026-10-28 → 2026-11-07 (ongoing) · [HIGH]

**OpenVox Puppet-server — CVE-2026-115731 / CVE-2026-115732 — pre-auth RCE via agent reports**
The OpenVox GHSA (ffr6-rwpm-p5wq) documents an RCE path where an agent holding a signed certificate submits a crafted JSON run report whose malicious event object executes on the Puppet server. CVE-2026-115731 scored CVSS 4.0 of **9.4**. A sibling CVE-2026-115732 (CVSS 9.0) is a certificate-name authorization bypass enabling node impersonation; in non-default configurations it allows an attacker to inject exported resources into arbitrary agent catalogs — i.e., push code to other managed nodes. A working PoC is in the GHSA. No in-the-wild exploitation confirmed in-window, but the exploitation primitive is low-complexity. Fixed: **openvox-agent 8.32.0 / 9.3.0**, **openvox-server 8.18.0 / 9.2.0**, **openvoxdb 8.18.0 / 9.2.0**; **Puppet Enterprise 2023.8.13, 2025.12.1, 2026.0.1**. **Open Source Puppet will NOT receive fixes** — mandatory migration. Practitioner actions: patch OpenVox and PE; audit autosigning — several defenders are pointing out that broad autosigning turns this from "any provisioned agent" to "anyone on the provisioning network"; check server logs for unusual report submissions.
[source](https://www.openwall.com/lists/oss-security/2026/11/03/14) · [source](https://securityonline.info/puppet-server-rce-cve-2026-115731-poc/) · [source](https://dailysecurityreview.com/?p=45333) · Date: 2026-11-03 → 2026-11-07 (ongoing) · [HIGH]
