## Telecom

- **QTFY / Nanjing Xinjiuwei Chinese state-sponsored operation — DOJ/FBI seize QScan + QTRouter (unsealed Aug 26, broad Aug 27 press).** DOJ affidavits attribute an eight-year (≥2018) campaign against NASA, the Federal Reserve, DOJ, the US Senate, DoE, HHS/NIH, hospitals, defence contractors, power companies **and telecom providers** to a private company (Nanjing Xinjiuwei Network Technology) contracting for the Chinese state, under the operator name "QTFY." Two platforms were seized: **QScan** (automated infection of IoT and edge hardware — routers, cameras, smart-home devices) and **QTRouter**, an anonymisation mesh built on those infected devices plus rented VPS and commercial proxies, used to route all C2 traffic so it never looks like it originates in China. No US telco is publicly named yet, and the DOJ has not attributed a specific 2024–2026 telco intrusion to QTFY, but the pattern (long-dwell, edge-device-based, anonymised through a router botnet) is the exact profile most US operators are hunting against in the wake of Salt Typhoon. Treat the router-mesh IOCs (when CISA publishes) as the near-term action item. — [DOJ press release (public affairs)](https://www.justice.gov/opa/pr/justice-department-and-fbi-seize-platforms-operated-and-used-china-state-sponsored-hackers) · [Time](https://time.com/article/2026/08/27/china-hack-federal-agencies-cybersecurity-qtfy-senate-nasa/) · [CNBC](https://www.cnbc.com/2026/08/26/china-hacker-federal-reserve-doj-nasa.html) · Date: **2026-08-26** (court docs unsealed) / **2026-08-27** (broad reporting) · **HIGH**

## General high-severity

- **CISA KEV — three new entries Aug 27; FCEB remediation deadline Sep 10, 2026.**
  - **CVE-2026-53362 — Linux Kernel "ipv6_frag_escape" container escape and local privilege escalation.** Out-of-bounds write in `__ip6_append_data()` in the paged-allocation branch used for `MSG_MORE`, `NETIF_F_SG`, and large fragments. Trigger is a UDPv6 socket combining `MSG_MORE` with `MSG_SPLICE_PAGES`. Chains into a dirty-pagetable primitive that gives arbitrary kernel read/write, overwrites process creds to uid=0, patches `avc_denied()` to bypass SELinux, and escapes the container to the host via `core_pattern`. Vendor fixes across seven stable kernel series; Red Hat, SUSE, Ubuntu all shipping. Distinct from CVE-2026-43284 (Dirty Frag) and CVE-2026-46300 (Fragnesia). If you run multi-tenant containers on Linux kernels 6.1.x/6.6.x/6.12.x/6.18.x/7.1.x behind the fixed cutoffs, this is the whole ballgame. — [Red Hat RHSB-2026-009](https://access.redhat.com/security/vulnerabilities/RHSB-2026-009) · [CIQ mitigation note (Rocky 10)](https://kb.ciq.com/article/security-advisories/cve-ipv6-frag-escape-mitigation) · [SentinelOne DB](https://www.sentinelone.com/vulnerability-database/cve-2026-53362/) · [Ubuntu tracker](https://ubuntu.com/security/CVE-2026-53362) · **CRITICAL**
  - **CVE-2023-49105 — ownCloud pre-auth file access/modify/delete, fresh 2026 in-the-wild evidence.** Hunt.io on Aug 13 found an exposed staging server holding 1,310 files across 86 subdirs — custom exploit scripts, exfiltration logs, offensive tooling, and stolen data from a Philippine nuclear research organisation. The recovered Python exploit sets the `OC-Credential` parameter to a target account and signs it with the empty secret to pull nuclear material records, reactor data, personnel files and encryption keys via WebDAV. Only prerequisites: know the username and the account has no signing key (the default). ownCloud pushed the fix in Nov 2023; two-year-old holes are still cheaper than 0-days if you never patched. — [GBHackers write-up](https://gbhackers.com/cve-2023-49105-flaw-exploited/) · [Ambionics exploit repo](https://github.com/ambionics/owncloud-exploits) · [SentinelOne DB](https://www.sentinelone.com/vulnerability-database/cve-2023-49105/) · [ownCloud advisory](https://owncloud.com/blogs/immediate-action-required-critical-security-updates-for-owncloud/) · **HIGH**
