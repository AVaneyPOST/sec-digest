## General high-severity

- **CISA KEV additions — CVE-2026-109618 and CVE-2026-109619 (PHP "PHP2Shell")** — [NOTABLE → CRITICAL for internet-facing PHP]. CISA added both to KEV on 2026-10-26 with a short remediation window. Memory corruption / stale internal request-state in PHP's SAPI handling; unauthenticated RCE under common configurations (Apache mod_php, PHP-FPM, php-cgi, FrankenPHP, LiteSpeed). HKCERT states exploitation in the wild; VulnCheck has a working ASLR-bypass RCE on x86-64 with the recommended production config. Fixes: PHP 8.2.35 / 8.3.36 / 8.4.27 / 8.5.12. Partial mitigation: `session.upload_progress.enabled=Off` — not a substitute. Any telco subscriber portal, provisioning web app, or vendor appliance that ships PHP (there are many) is in scope; prioritise anything that exposes `php-fpm` or `php-cgi` directly, or terminates HTTP for a hostile edge. Date: 2026-10-26. [CISA alert](https://www.cisa.gov/news-events/alerts/2026/10/26/cisa-adds-two-known-exploited-vulnerability-catalog) · [Rapid7 analysis](https://www.rapid7.com/blog/post/etr-cve-2026-109618-and-cve-2026-109619-critical-unauthenticated-remote-code-execution-in-php/) · [HKCERT bulletin](https://www.hkcert.org/security-bulletin/php-multiple-vulnerabilities_20261022) · [SANS ISC diary](https://isc.sans.edu/diary/rss/33440?mid=1).

- **Amazon: PHP2Shell exploitation attempts predate the patch by ~4 days** — [NOTABLE]. BleepingComputer reports Amazon's threat team saw the first exploitation attempts on 2026-10-17, before PHP's 2026-10-21 release. PHP maintainers assert none of the pre-patch PoCs were functional. Multiple commodity PoCs within hours of disclosure, Cloudflare observed millions of attempts. Confirmed successful RCE in production remains contested across sources. Rebuild assumption: logs from Oct 17 onward are the earliest honest start for retro-hunting on affected hosts. Date: 2026-10-26 (BleepingComputer). [BleepingComputer](https://www.bleepingcomputer.com/news/security/amazon-says-php2shell-exploitation-began-4-days-before-patches) · [The Hacker News](https://thehackernews.com/2026/10/someone-tried-to-exploit-php2shell-4.html) · [SecurityWeek](https://securityweek.com/php2shell-exploitation-started-days-before-patches).

## Worth watching

Open items from the preceding week that remain active and are likely to generate telco-relevant follow-ups:

- **Arista VeloCloud Orchestrator — CVE-2026-114625 (CVSS v3 9.9 / v4 9.4)**, authenticated SQLi where any role (including Enterprise Read Only) escalates to local superuser-operator. Third VCO zero-day in four months. KEV listing had not landed as of 2026-10-23. VCO is deployed by several MVNOs and enterprise/wholesale carriers that run SD-WAN for operator-run managed services — direct telecom relevance. Fixed: 5.2.3.18, 6.1.3.10, 6.4.2.12. [Arista SA-0199](https://www.arista.com/en/support/advisories-notices/security-advisory/24838-security-advisory-0199) · [BleepingComputer](https://bleepingcomputer.com/news/security/arista-patches-new-velocloud-orchestrator-zero-day-exploited-in-attacks) · [SecurityWeek](https://securityweek.com/attackers-exploit-third-velocloud-orchestrator-zero-day-in-four-months).

- **Cisco Secure Email Gateway — CVE-2026-76519 (CVSS 9.8)**, path traversal in AMP attachment handling → unauth root RCE via a crafted mail attachment. Cisco PSIRT confirms active exploitation; Cisco contacted Secure Email Cloud customers with observed IOCs. Second SEG RCE exploited in the wild since mid-September (after CVE-2026-76461). Fix: Content Scanner Tools ≥ 25.3.0.5525. SEG is widely deployed by telcos as perimeter/customer mail security — look for "System Security" log entries. [BleepingComputer](https://www.bleepingcomputer.com/news/security/cisco-patches-actively-exploited-secure-email-gateway-zero-day/amp/) · [SecurityWeek](https://www.securityweek.com/cisco-warns-of-exploited-secure-email-gateway-vulnerability/) · [The Stack](https://www.thestack.technology/cisa-cisco-cve-to-kev/).

- **GitLab self-managed — CVE-2026-110264 (CVSS 10)**, integer overflow in GitLab's regex compiler reachable from config file parsing → unauth RCE. Backported to 7.0; the vulnerable path has been in the codebase for ~12 years. Fixes: 19.5.1 / 19.4.3 / 19.3.6 / 19.2.9 / 19.1.9 / 19.0.10 / 18.11.13. GitLab.com already patched. [BleepingComputer](https://www.bleepingcomputer.com/news/security/gitlab-warns-of-new-max-severity-code-execution-vulnerability/) · [SOC Prime](https://socprime.com/?p=55407) · [OpenCVE](https://app.opencve.io/cve/CVE-2026-110264).

- **Node.js Brotli OOB write — CVE-2026-111497 ("Node2Shell", CVSS v4 9.2)**, in the Brotli decoder bundled with Node.js. Requires app to decompress attacker-controlled Brotli. Imperva demonstrated code execution on the stock Linux arm64 24.22.0 image. Fixed: 22.23.4 / 24.22.1 / 26.12.1 and Bun 1.4.4. All EOL Node lines (20.x and earlier) carry the vulnerable decoder with no upstream fix. [The Hacker News](https://thehackernews.com/2026/10/researchers-demonstrate-node2shell-rce.html) · [HeroDevs](https://www.herodevs.com/blog-posts/cve-2026-111497-node2shell-node-js-brotli-rce) · [Rescana](https://www.rescana.com/post/nodejs-cve-2026-111497-node2shell-brotli-rce-october-2026).

- **BeyondTrust Remote Support — CVE-2026-102764 (CVSS 9.3), ARMORY CASTLE (ex-UNC5221)**. Origin-validation flaw in an internal messaging component; Mandiant: unauthenticated RCE → full host control + every stored/brokered credential. Exploited as 0-day on at least one self-hosted appliance on 2026-08-29; a second hosted instance also hit. KEV since 2026-10-16. Fix: BT26-05-RS; <24.3.1 must upgrade first. BeyondTrust appliances broker privileged access into carrier NOC/OSS/BSS — assume compromise if unpatched before Oct 16. [BleepingComputer](https://bleepingcomputer.com/news/security/beyondtrust-patches-zero-day-exploited-in-attacks-since-august) · [CSO Online](https://www.csoonline.com/article/4236421/beyondtrust-zero-day-tied-to-chinese-spies-puts-remote-support-users-on-alert.html) · [SecurityWeek](https://securityweek.com/chinese-apt-exploited-beyondtrust-vulnerability-as-zero-day).

Only Nextcloud All-in-One / in-Nextcloud CODE app is affected; standalone/Docker/RPM/DEB Collabora is not. Fix: richdocumentscode 26.4.303. Disabling the app does not close the flaw. [BleepingComputer](https://www.bleepingcomputer.com/news/security/hackers-exploit-collabora-rce-flaw-to-backdoor-nextcloud-servers/) · [eSecurity Planet](https://www.esecurityplanet.com/threats/news-collabora-nextcloud-cve-2026-110447/) · [Debian tracker](https://security-tracker.debian.org/tracker/CVE-2026-110447).
