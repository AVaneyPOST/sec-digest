- **Juniper Junos OS J-Web — three unauthenticated-RCE / auth-bypass CVEs still active
  patch items for carrier edges** [HIGH]. Carryover from the 2026-10-14 Juniper bundle but
  worth flagging again because it fell under the broader Patch Tuesday noise. CVE-2026-101954
  (improper authentication in J-Web + NETCONF, unauthenticated root config access, CVSS
  listed as 9.3–9.8 depending on source), CVE-2026-101986 (J-Web auth bypass), CVE-2026-101956
  (J-Web unauth root command execution). Fixed trains include 23.2R2-S7.7, 23.4R2-S8.13,
  24.2R2-S5.5, 24.4R2-S5, 25.2R2-S2, 25.4R1-S3, 25.4R2, 26.2R1-S2, 26.2R2, 26.4R1. No
  workaround for 101954. Why it matters for a telco: J-Web on operator-facing MX / PTX /
  SRX edges is a known foothold path onto routing control planes; and SRX on the enterprise
  perimeter sits in front of plenty of SIP/IMS trunking paths. Juniper's SIRT says no
  observed exploitation.
  [OpenCVE CVE-2026-101954](https://app.opencve.io/cve/CVE-2026-101954),
  [OpenCVE CVE-2026-101986](https://app.opencve.io/cve/CVE-2026-101986),

  [CSA Singapore AL-2026-146](https://www.csa.gov.sg/alerts-and-advisories/alerts/al-2026-146/).

- **Signal RingRTC CVE-2026-113380 — carryover for operator-adjacent OTT deployments**
  [NOTABLE]. Still relevant 2026-10-25: patched in RingRTC 2.72.0 (jim-signal commit 2026-09-04)
  which adds a separate termination flag and five-second shutdown limits. CVSS v4.0 9.3,
  affects RingRTC < 2.72.0; signal.org has not published an advisory listing the exact

  use Signal for IR bridges / privileged OOB comms. Same FSM-queue saturation pattern
  (256-entry bounded queue) is a template for your own WebRTC / IMS-RTP teardown paths.
  [CyberInsider writeup](https://cyberinsider.com/?p=346490),
  [SQ Magazine writeup](https://sqmagazine.co.uk/signal-ringrtc-flaw-audio-after-hangup.md),
  [Malwarebytes writeup](https://www.malwarebytes.com/?p=479546).

## General high-severity

- **No new confirmed CISA KEV addition for 2026-10-24 or 2026-10-25.** Last confirmed add
  is CVE-2026-110447 (Collabora Online built-in CODE server OS command injection) on
  2026-10-23. If you gate change-control on KEV adds, nothing new to action here.

- **PHP RCE pair CVE-2026-109618 / CVE-2026-109619 — exploitation window still live**
  [CRITICAL]. Fixes shipped 2026-10-21 (PHP 8.2.35 / 8.3.36 / 8.4.27 / 8.5.12). CISA and
  Unit 42 updated their advisories 2026-10-23; CISA has a SIGMA detection rule. No new
  vendor update today. `session.upload_progress.enabled=0` is a stopgap only; mod_php is
  the highest-risk configuration. The watch item is still mod_php fleets on edges that
  accept multipart POSTs — mass internet-scan activity against the pattern was expected
  to tick up through this weekend.
  [Unit 42 brief](https://unit42.paloaltonetworks.com/cve-2026-109618-cve-2026-109619/),
  [Rapid7 writeup](https://www.rapid7.com/blog/post/etr-cve-2026-109618-and-cve-2026-109619-critical-unauthenticated-remote-code-execution-in-php/).

- **PHP CVE-2026-115560 (session handling) — remains unpatched** [HIGH]. CERT-AGID's
  2026-10-24 bulletin elevated this to confirmed-but-unpatched (separate from the 109618 /
  109619 pair that was patched 2026-10-21). No new PHP release today; the CVE ID still is
  not indexed by NVD per the previous digest's spot-check. Treat as the next PHP watch
  item: keep the `session.upload_progress` stopgap in place and keep WAF/IDS rules on
  multipart POSTs.
  (No new primary source surfaced in the 2026-10-25 window; see
  [ts2 writeup citing CERT-AGID](https://ts2.tech/en/phps-new-session-flaw-requires-more-than-a-version-check/)
  from 2026-10-24.)

- **Microsoft Secure Boot — Windows Production PCA 2011 expired 2026-10-19** [NOTABLE,
  posture item]. One week into the expiry window. Devices that have not received the
  Windows UEFI CA 2023 certificates stop getting new boot-chain security updates:
  Windows Boot Manager updates, Secure Boot DB updates, revocation list updates, and
  mitigations for newly discovered boot-level vulnerabilities. Devices still boot. Most
  endpoints should pick up the new certs via Windows Update, but older or offline
  firmware may need an OEM BIOS update (Dell dual-cert strategy from late 2024 for
  in-support models; HP enterprise devices need SBKPFV3). Why this matters now:
  2026-10-24 BlackX / APT41 UEFI-bootkit reporting illustrates exactly the kind of boot-
  chain tampering these updates mitigate. Verify fleet SB cert coverage this week.
  [Microsoft support KB](https://support.microsoft.com/en-gb/topic/windows-secure-boot-certificate-expiration-and-ca-updates-7ff40d33-95dc-4c3c-8725-a9b95457578e),
  [Neowin writeup](https://www.neowin.net/news/certificates-for-one-of-windows-11s-hardware-requirements-expire-soon-here-is-what-to-know/).
