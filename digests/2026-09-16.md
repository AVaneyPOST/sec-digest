**CVE-2026-90711 — proxy-addr IP spoofing (CVSS 9.1), disclosed 2026-09-15.** Bug in the Node.js `proxy-addr` module (v1.1.0 → 2.0.7) that backs Express.js `req.ip` / `req.ips`. A trust-subnet written in IPv4-mapped IPv6 notation with an IPv4-sized prefix (e.g. `::ffff:10.0.0.0/8` instead of `::ffff:10.0.0.0/104`) is accepted without error but trusts every IPv4 address on the internet rather than the block it names. Because the socket peer then becomes trusted at hop 0, any unauthenticated client can supply an arbitrary `X-Forwarded-For` header and control the address the application reads — defeating IP-based access control, rate limiting, geolocation, and audit logging in one shot. Fixed in `proxy-addr` 2.0.8 and re-published in Express 5.2.1. Practitioner take: this is a fail-open regression that likely lurks in dependency lockfiles across a large fraction of Node-hosted web apps (management portals, customer-facing self-service, third-party admin UIs). Enumerate Node-based estate for `proxy-addr` <2.0.8 and audit any `set('trust proxy', …)` config lines for IPv4-mapped-IPv6 subnets with prefix shorter than /97 — that's the trigger. Where in doubt, express IPv4 ranges in plain IPv4 notation. Sources: [Strix CVE-2026-90711](https://www.strix.ai/cve/CVE-2026-90711), [VulDB](https://vuldb.com/cve/CVE-2026-90711), [TheHackerWire analysis](https://www.thehackerwire.com/proxy-addr-ip-spoofing-bypass-cve-2026-90711/), [THREATINT](https://cve.threatint.com/CVE/CVE-2026-90711). **HIGH** (blast radius; Express.js middleware).
