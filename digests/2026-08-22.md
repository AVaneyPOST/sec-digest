## TL;DR

- **Entra ID CVE-2026-69836 — CVSS 10.0 unauth RCE, exploited in the wild, MS-side already fully mitigated.** Deserialization of untrusted data (CWE-502); no auth, no user interaction, low complexity, network-reachable — the CVSS-triple-worst combination. CVE published 2026-08-20; MS advisory + coverage cascade 08-21. Microsoft says it has mitigated the flaw across all Entra ID tenants before disclosure and that customers do not need to install updates or change configurations. Attribution / TTP / dwell-time all withheld. Exploit code not yet public. Practical read for a defender: nothing to install, but any Entra-ID tenant should treat the window before 08-20 as "assume-exposed" for signing-key / conditional-access / privileged-role review — MS have declined to say when exploitation started or how many tenants were touched. **CRITICAL**.
- **TrueConf Server CVE-2026-72529 (CVSS 9.8) + CVE-2026-72530 — CISA KEV additions dated 2026-08-20 (missed by yesterday's digest).** Federal deadline is **3 days** on 72529 (the unauth-RCE half) and 2 weeks on 72530 (the sandbox-escape half). Chain exploited by Kaspersky-attributed **Head Mare** APT against Russian and Belarusian targets in critical sectors (instrumentation, electronics, transport, energy, IT, software). End-to-end: unauth attacker → TCP/4307 → undocumented function → arbitrary script → sandbox escape → SYSTEM on the TrueConf host → replace signed client installers → PhantomCore + PhantomGraph pushed to every meeting participant on next update. Patched **June 18 2026** in 5.3.9 / 5.4.9 / 5.5.5 — the exposure window covers all unpatched installs since. **CRITICAL**.
- **Operation CameraSwarm (Hunt.io) — 14,500+ Dahua IP cameras hijacked, campaign focus shifted mid-run to Russian and CIS telecom-operator netblocks.** Attacker exposed its own HTTP directory (2,616 files, 407 MB toolkit + logs — Hunt.io mirrored). Access via credential brute-force plus Dahua's own P2P cloud-relay abuse (serial-number-only reach into NAT'd cameras) and RPC auth-bypass paths; persistent backdoor account deployed to 1,923 cameras. Language artifacts point to a Russian-speaking operator, but no formal APT / government attribution. Infrastructure aged **>1 year** pre-campaign. **HIGH — telecom-adjacent** (the netblock-selection stage moved deliberately to CIS carrier ASNs; if you're a CIS operator, expect your subscriber-side / small-cell / video-monitoring IoT surface to be in this dataset).
- **Zimbra CVE-2026-73570 broadening — CERT Polska now attests to attacks independent of the BE-CCB advisory.** No change to the vuln (CVSS 8.9, SNMP-notification command injection, patched 07-20 in 10.1.20) but the exploited-in-wild evidence base has grown from a single-CERT observation to two. Detection guidance in-window: watch `/var/log/zimbra.log` for stopped→running / running→stopped transitions on unknown service names — the SNMP-notify hook path leaves that fingerprint. Same 12,100-server Shadowserver population; same ITW campaign; higher confidence. **HIGH** (carry-forward).
- **Telecom-operator ransomware — NTE Italia (Catanzaro; engineering + telecoms) posted on Panzer leak site 08-21.** Small Italian regional provider. No independent breach confirmation yet — standard tracker-hold caveat — but listed here because it is a rare in-window carrier-vertical leak-site posting worth watching for a follow-up confirmation. **NOTABLE**.

## General high-severity

**Microsoft Entra ID CVE-2026-69836 — CVSS 10.0 unauth RCE, exploited in the wild, MS-side already mitigated** — [Microsoft MSRC — CVE-2026-69836](https://msrc.microsoft.com/update-guide/vulnerability/CVE-2026-69836), [BleepingComputer — Max severity Entra ID flaw exploited](https://www.bleepingcomputer.com/news/microsoft/microsoft-warns-of-max-severity-entra-id-flaw-exploited-in-attacks/), [The Hacker News — Entra ID flaw CVSS 10.0](https://thehackernews.com/2026/08/microsoft-entra-id-flaw-cvss-100.html), [The Register — Microsoft sounds alarm on perfect-10 Entra ID flaw](https://www.theregister.com/cyber-crime/2026/08/21/microsoft-sounds-alarm-as-perfect-10-entra-id-flaw-comes-under-attack/5290925), [Help Net Security — Critical Entra ID vulnerability exploited](https://www.helpnetsecurity.com/2026/08/21/microsoft-entra-id-vulnerability-cve-2026-69836/), [SOCRadar — CVE-2026-69836 Entra ID RCE](https://socradar.io/blog/cve-2026-69836-microsoft-entra-id-rce/), [Tenable CVE-2026-69836](https://www.tenable.com/cve/CVE-2026-69836) — CVE published 2026-08-20, coverage cascade 2026-08-21 — **CRITICAL**
This is the **highest-severity Entra ID / Azure AD flaw ever assigned**, matching the CVSS-3.1 ceiling: `AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H`. Root cause is **deserialization of untrusted data (CWE-502)** in Entra ID. Discovered internally by Microsoft principal security engineer Robert Fitzpatrick. Microsoft has confirmed **active in-the-wild exploitation** but has withheld the identity of the actor, when exploitation began, how widespread, or what post-exploitation looks like. The vulnerability is in Microsoft's managed identity plane, so mitigation is a Microsoft-side rollout — the advisory explicitly states no customer patching, config change, or action is required. Exploit code is not yet public. For a red / blue team: the "no action" language is accurate as an instruction, but it is not a clean bill of health — MS's silence on the exploitation window means any Entra tenant should treat the period before 08-20 as an "assume-touched" prior and audit accordingly. Highest-value forensic look: recent conditional-access policy changes, service-principal creations / consent grants, application-permission escalations, PIM eligible-role activations, and any new signing key registrations in the past 30-60 days — the type of primitives a max-severity IAM-plane RCE would enable. If you have SIEM coverage on Entra sign-in / audit logs, hunt back to the earliest retention. Given no CVSS-10 Entra bug has previously landed, this is the most consequential single-vulnerability disclosure of the month regardless of vertical.

**TrueConf Server CVE-2026-72529 (CVSS 9.8) + CVE-2026-72530 — CISA KEV additions 2026-08-20 (correction: missed by yesterday's digest); Head Mare APT chained them for supply-chain client-installer trojanization** — [CISA — Adds two known exploited vulnerabilities to catalog](https://www.cisa.gov/news-events/alerts/2026/08/20/cisa-adds-two-known-exploited-vulnerabilities-catalog), [SecurityWeek — CISA urges immediate patching of TrueConf](https://www.securityweek.com/cisa-urges-immediate-patching-of-exploited-trueconf-vulnerabilities/), [Kaspersky ICS-CERT — Head Mare TrueConf](https://ics-cert.kaspersky.com/publications/reports/2026/08/12/head-mare-exploits-vulnerabilities-in-trueconf-server-to-deliver-phantomcore-malware/), [Kaspersky ICS-CERT — KLCERT-26-057 advisory](https://ics-cert.kaspersky.com/advisories/2026/08/11/trueconf-server-missing-authentication-for-critical-function/), [Securelist — Head Mare targets TrueConf with PhantomCore](https://securelist.com/tr/head-mare-targets-trueconf-server-with-phantomcore/120988/), [BleepingComputer — TrueConf trojanized client installers](https://www.bleepingcomputer.com/news/security/hackers-breach-trueconf-to-trojanize-client-installers-with-backdoors/), [The Hacker News — TrueConf client installers replaced with PhantomCore](https://thehackernews.com/2026/08/head-mare-exploits-trueconf-flaws-to.html), [Security Affairs — CISA adds TrueConf to KEV](https://securityaffairs.com/197602/security/u-s-cisa-adds-trueconf-server-flaws-to-its-known-exploited-vulnerabilities-catalog.html), [SC Media — TrueConf flaws in KEV](https://www.scworld.com/news/trueconf-flaws-enabling-attacks-on-meeting-participants-added-to-kev-catalog) — Kaspersky first disclosure 2026-08-11, KEV addition 2026-08-20, patched 2026-06-18 — **CRITICAL**
Two-CVE chain in TrueConf Server (a Russian-vendor on-prem videoconferencing product used in enterprise and government deployments across Russia / Belarus and parts of Eastern Europe). Chain shape:
- **CVE-2026-72529 (CVSS 9.8; KLCERT-26-057)** — Missing authentication for critical function. Unauth remote attacker with network reach to TCP/4307 (open by default per TrueConf docs) can invoke an undocumented function that executes arbitrary scripts inside a restricted script sandbox on the TrueConf server.
- **CVE-2026-72530 (KLCERT-26-058)** — Code injection. Chained to CVE-2026-72529, escapes the script sandbox to arbitrary OS command execution as SYSTEM on the underlying Windows host.
Chain end-state: SYSTEM on the TrueConf server, followed by **replacement of the signed client-installer distribution files** hosted for auto-update. Every meeting participant pulling the next client update receives a trojanized installer carrying **PhantomCore** and **PhantomGraph** backdoors — this is a classic client-side supply-chain compromise via a compromised update server. Kaspersky first flagged the campaign 2026-08-11 (attack activity dating to July) and attributes it to **Head Mare**, a group Kaspersky has re-classified from hacktivist to APT this year (targets in Russia and Belarus across instrumentation, electronics, transportation, energy, IT, software). Patched by the vendor **2026-06-18** in versions 5.3.9 / 5.4.9 / 5.5.5. CISA KEV addition was Wednesday 2026-08-20; federal deadline is **3 days on 72529 (Sat 08-23) and 2 weeks on 72530 (Wed 09-03)**. Yesterday's digest ran the "no KEV additions dated 2026-08-20" framing — that was wrong; the two-TrueConf-addition alert is the sole KEV entry that day, matches the same pattern as the MLflow correction one cycle earlier. If you run TrueConf on-prem, especially exposed to a Russia / Belarus / CIS user population, treat this as **patch now and audit installer hashes back to at least June 18** — the trojanized-installer window overlaps that patch date, so any client rolled out from the same TrueConf server between then and today may be compromised.

**E4del + PINHOLE — novel FTP-banner dead-drop resolver (DDR) technique for staging Windows RATs** — [BleepingComputer — Hackers abuse FTP server banners](https://www.bleepingcomputer.com/news/security/hackers-abuse-ftp-server-banners-to-deliver-new-windows-malware/) — first observation July 2026 by MalwareHunterTeam, new infrastructure observed August 2026
Novel enough to flag: an FTP server's greeting banner (the text a client sees before authenticating) is being used to pass staging commands to a `.LNK`-launched loader on the victim, which then pulls E4del (Node.js RAT, Electron-packaged, signed and masquerading as Discord) or PINHOLE. Interesting because most DDR patterns use HTTP-header abuse, Wikipedia/Github-page abuse, DNS TXT abuse, or public-key-server abuse — FTP banners are less monitored, less content-filtered at the perimeter, and don't require the client to authenticate to receive the banner. Not currently high-severity by volume, but detection-engineers should add "outbound FTP with no LIST/RETR follow-up" as a small hunt behavior.
