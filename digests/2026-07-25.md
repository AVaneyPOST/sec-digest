# Security digest — 2026-07-25

Window: last 24h ending 2026-07-25 04:06 UTC.

## TL;DR

- **Certighost — public PoC turns any low-priv AD user into Domain Admin against unpatched AD CS.** Researchers H0j3n and Aniq Fakhrul published `certighost.py` on 24 Jul, weaponising CVE-2026-54121 (Microsoft's July Patch Tuesday, CVSS 8.8, improper authorization). The exploit abuses an AD CS enrollment "chase" fallback to obtain a certificate as a Domain Controller, PKINIT-authenticates as that DC, and DCSyncs `krbtgt` — full-domain compromise. Any enterprise CA not yet on the July 2026 cumulative is trivially owned; the 8.8 base score buries the actual impact.
- **Bing Images SVG RCE — CVE-2026-32194 / CVE-2026-32191 (CVSS 9.8 each), unauth pre-auth RCE inside Microsoft's image pipeline.** XBOW disclosed on 24 Jul that a crafted SVG uploaded via "Search by Image", or merely hosted anywhere and referenced via the `imgurl` parameter (Bingbot fetches it), executed as `NT AUTHORITY\SYSTEM` on the Windows workers and as root on the Linux fleet — ImageMagick-style delegates left enabled on the conversion tier. No customer action; Microsoft has reconfigured the workers. The interesting artefact is the class of bug still living inside hyperscaler image plumbing in 2026.
- **Golden Chickens / TAG-195 back with four new malware families.** Recorded Future / Insikt on 24 Jul: TinyEgg (lightweight profiler/loader), ChonkyChicken (Chrome credential + live session theft), a modularized ChonkyChicken variant, and ChromEggscalator. TinyEgg is being distributed by TAG-127 via ClickFix social engineering. Shared C2, persistence, and obfuscation across the four look like a coordinated architectural refresh of the MaaS rather than incremental drift — expect broad customer uptake in the next few weeks.
- **FakeGit — 7,600 GitHub repos across ~6,600 accounts pushing SmartLoader / StealC.** Trend Micro / press on 24 Jul: repos posed as skills / MCP servers for Gmail, WhatsApp, Databricks, Jenkins, Docker; ZIPs chained a LuaJIT loader → SmartLoader → StealC; ~14M combined downloads. Attributed to a continuation of the "Water Kurita" cluster last seen pushing Lumma. Developer workstations and CI runners are the target surface.

## General high-severity

- **CVE-2026-54121 "Certighost" — public PoC drops for the July Patch Tuesday AD CS domain-compromise bug.** Microsoft's July 14 update fixed the improper-authorization flaw (base CVSS 8.8), but the primitive is a straight full-domain compromise for any Enterprise CA that isn't on the cumulative. Researchers **H0j3n** and **Aniq Fakhrul** published `certighost.py` on 24 Jul with a technical write-up: any low-privileged AD user can trigger an enrollment "chase" fallback in AD CS, obtain a certificate *for a Domain Controller*, PKINIT-authenticate as that DC, and DCSync `krbtgt` — the classic path to Domain Admin, now trivially reachable. Weaponised public PoC + patch-lag reality means detection should presume in-the-wild use within days. Detection cues: unusual PKINIT logons whose subject is a DC account, certificate templates chased by non-server principals, and `ESC-family` template audits from the July fix's log/audit paths. Practical mitigation: patch the CA and every DC on the July cumulative; audit certificate templates for auto-enrollment paths that a low-priv account can reach; monitor Kerberos S4U2Self and DCSync events. [Cyber Security News](https://cybersecuritynews.com/certighost-active-directory-cs-flaw/), [aniqfakhrul PoC repo](https://github.com/aniqfakhrul/CVE-2026-54121), [H0j3n gist / write-up](https://gist.github.com/H0j3n/a5ef2609b5f2944ac2390a191a534c26), [CyberKendra](https://www.cyberkendra.com/2026/07/new-certighost-flaw-lets-any-domain.html). Date: 2026-07-24 (PoC / write-up). [CRITICAL]

- **CVE-2026-32194 & CVE-2026-32191 — unauthenticated pre-auth RCE inside Bing Images (CVSS 9.8 each).** XBOW's public write-up dropped on 24 Jul. A crafted SVG uploaded via Bing's "Search by Image" (32194), or hosted anywhere on the internet and referenced via the `imgurl=` query parameter (32191) so that Bingbot itself fetches it, executed OS commands as `NT AUTHORITY\SYSTEM` on the Windows image-processing workers and as `root` on the Linux fleet. Root cause: dangerous ImageMagick-style delegates left enabled on the conversion tier. No auth, no cookies, no click — the reachability from `imgurl` means an unauthenticated attacker could compel Microsoft's own infra to fetch and process attacker-controlled SVGs. Microsoft has already reconfigured the workers; there is no customer-side patch, and no external victims to notify. The item matters for two reasons: (a) it's a live example of decades-old ImageMagick-delegate risk still shipping inside hyperscaler pipelines in 2026, and (b) it should refresh anyone's threat model for internal image-conversion services that accept SVG. Hunt: prior anomalous processes spawned by ImageMagick/Ghostscript/convert-family binaries on any Linux estate that accepts user-supplied SVG. [XBOW blog](https://xbow.com/blog/bing-images-rce-vulnerabilities), [Cyber Security News](https://cybersecuritynews.com/bing-images-vulnerability/), [CyberKendra](https://www.cyberkendra.com/2026/07/bing-images-bugs-let-anyone-run-code-as.html). Date: 2026-07-24. [CRITICAL]

- **Golden Chickens (TAG-195) — MaaS returns with four new malware families.** Recorded Future / Insikt Group published on 24 Jul: the operator behind `more_eggs` (a long-running JScript backdoor with strong ties to FIN6 and other financially motivated crews) has released **TinyEgg** (lightweight loader/profiler), **ChonkyChicken** (Chrome credential theft + live session hijack), a modularized ChonkyChicken variant, and **ChromEggscalator** (Chrome-targeted privilege / capability escalator). TinyEgg is currently being distributed via ClickFix-style social engineering by a separate access-broker cluster (TAG-127). Shared C2 infrastructure, persistence patterns, and obfuscation across the four families argue for a coordinated architectural refresh of the MaaS platform, not incremental drift — which historically has meant broad customer uptake by unrelated intrusion sets within weeks. Practical read: defensive teams should update session-hijack detections (browser-process behavioral analytics) and rebuild their ClickFix landing-page baselines. [The Hacker News](https://thehackernews.com/2026/07/golden-chickens-resurfaces-with-four.html), [CyberPress](https://cyberpress.org/golden-chickens-unleashes-tinyegg/), [GBHackers](https://gbhackers.com/four-modular-malware-families/), [SC World](https://www.scworld.com/brief/golden-chickens-malware-as-a-service-resurfaces-with-four-new-families). Date: 2026-07-24. [HIGH]

- **FakeGit — 7,600 GitHub repos across ~6,600 accounts distributing SmartLoader / StealC.** Trend Micro published a large-scale "agentbaiting" campaign write-up on 24 Jul. Repos posed as **skills / MCP servers** for Gmail, WhatsApp, Databricks, Jenkins, and Docker; download ZIPs chained a **LuaJIT loader → SmartLoader → StealC**. Combined download count sits at roughly **14M**. Trend attributes to a continuation of the **"Water Kurita"** cluster previously seen pushing Lumma stealer. The novel wrapper here is agent-tooling bait — attackers riding the current agent/MCP hype cycle to reach developers who wouldn't previously have run an untrusted GitHub repo. Meaningful for anyone whose developer workstations, CI runners, or MCP host containers pull skills / MCP servers from unaudited public sources; treat MCP source auditing and skill signing as an active-threat item rather than a maturity roadmap goal. [The Hacker News](https://thehackernews.com/2026/07/fakegit-campaign-uses-7600-github.html), [BleepingComputer](https://www.bleepingcomputer.com/news/security/fakegit-campaign-uses-7-600-github-repos-to-push-smartloader-malware/). Date: 2026-07-24. [HIGH]

- **NodeBB — eight high-severity flaws fixed in 4.14.2, patches shipped 23 Jul, public disclosure 24 Jul.** Aikido's six-hour AI-assisted whitebox test found **stored XSS via unescaped ActivityPub profile URLs**, an **unauthenticated category/post disclosure via `/category/:cid/outbox`**, and multiple **authorization bypasses** exposing admin-only content and private chats. Affects installs `< 4.14.0`. No in-the-wild exploitation reported. Item worth noting because (a) NodeBB is deployed at meaningful community-forum scale, and (b) the ActivityPub outbox angle is a class of bug we should expect more of across federated software as more products bolt ActivityPub onto existing REST plumbing. [The Hacker News](https://thehackernews.com/2026/07/nodebb-patches-eight-ai-found-flaws.html), [CyberPress](https://cyberpress.org/nodebb-patches-eight-high-severity-flaws/), [Aikido write-up](https://www.aikido.dev/blog/eight-high-severity-vulnerabilities-nodebb). Date: 2026-07-24. [HIGH]

- **ChatGPT "AgentForger" — CSRF in the Workspace Agent Builder created rogue AI agents inside victim orgs (patched 8 Jun; public write-up 24 Jul).** Zenity Labs published on 24 Jul: the ChatGPT Workspace Agent Builder auto-submitted and executed the `initial_assistant_prompt` URL parameter, so a single phishing link could silently **create, authorize, and publish a rogue AI agent** inside a victim's workspace — inheriting already-consented connectors (Outlook, Gmail, Slack, Teams, Calendar), flipping the "Always ask" consent to "Never ask", and scheduling hourly runs. OpenAI fixed the underlying CSRF on 8 Jun; the value of the disclosure is the concrete threat model for agent-platform CSRF and the "AI insider" attack pattern that will recur across every hosted-agent product. If you're building or operating agent platforms with per-user connectors, this is your test case: assume the parameter is attacker-controlled, force explicit user confirmation for agent creation, do not auto-inherit connector consent across newly created agents. [The Hacker News](https://thehackernews.com/2026/07/chatgpt-agentforger-flaw-could-deploy.html), [SecurityWeek](https://www.securityweek.com/openai-fixes-chatgpt-agent-flaw-that-could-let-attackers-forge-an-ai-insider/), [Zenity Labs write-up](https://labs.zenity.io/p/agentforger-part-1-chatgpt-cross-site-agent-forgery). Date: 2026-07-24 (disclosure). [NOTABLE]

## Worth watching

- **Certighost detection is the actual work.** The PoC is public, the patch is nearly two weeks old, and Enterprise CA hosts are historically the last thing patched. The realistic operating assumption for the next 30 days is that any exposed AD CS with an unpatched CA has been probed. Immediate hunt: enumerate certificate templates that allow low-privileged principals to enroll, PKINIT logons whose subject is a computer/DC account originating from user endpoints, and DCSync events not tied to your usual replication service accounts. Longer-term: implement Microsoft's July audit-mode logging in advance of enforcement mode.
- **Bing Images RCE — internal image-conversion services should assume similar exposure.** Nothing to patch on Microsoft's side, but the class of bug (ImageMagick-family delegate enabled + user-controlled SVG) is decades old and will still be running inside a lot of enterprise pipelines. Sweep every internal service that accepts user-uploaded SVG or fetches remote SVGs on behalf of users (thumbnailers, PDF renderers, CMS attachment processors, chat-preview services) for `policy.xml` posture; disable dangerous delegates; sandbox the conversion tier as if it were internet-facing.
- **FakeGit / MCP-server supply chain.** MCP-server distribution is now an active supply-chain surface — the Trend / press write-up is a canary event, not an isolated one. If your dev estate runs unpinned or unsigned MCP servers pulled from public GitHub, treat that as an in-progress compromise vector: (a) inventory MCP servers currently loaded, (b) pin/sign them, (c) require review for new adoption, (d) monitor for LuaJIT-based loaders in developer-workstation EDR.
- **ChatGPT AgentForger generalises to every hosted agent platform.** Auto-submitted URL parameters + auto-inheritance of connector consent is a pattern, not a ChatGPT-specific bug. Anyone shipping or consuming hosted-agent platforms (ChatGPT, Claude, Copilot Studio, Zapier AI, custom) should review whether agent-creation endpoints accept URL-parameter payloads without a user gesture, and whether newly created agents inherit connector consent that a phishing link could exploit.
- **Oracle CPU July 2026 — telecom tranche still in flight.** The 21 Jul CPU (Rev 3 last-updated 23 Jul) shipped **168 patches for Oracle Communications, 122 remotely exploitable without authentication** — including the Session Border Controller (CVE-2026-2332, CVSS 9.1 via Jetty), Converged Application Server (CVE-2026-61223 / 61225), Diameter Signaling Router (LPE plus libssh in the Automated Test Suite), 5G Core Policy / NSSF / NRF (Spring Framework CVEs), and NEF (Tomcat + LibTIFF). Operators that batch monthly CPU patches for telecom infra should verify this one is actually landing, not waiting for the next cycle. [Oracle CPU July 2026](https://www.oracle.com/security-alerts/cpujul2026.html), [Tenable analysis](https://www.tenable.com/blog/oracle-july-2026-critical-patch-update-addresses-1235-cves).
- **FCC — conditional approvals for certain UAS and routers (Public Safety and Homeland Security Bureau, 24 Jul).** The Bureau granted time-limited exemptions from the Secure Networks Act Covered List for specific SKUs — e.g., the Gryphon Safety Online Parental Control Wi-Fi router and the Sercomm Air4992 Wi-Fi 7 router (both terminating 2028-01-10). Supply-chain read-across for MNO/MVNO CPE sourcing and for red teams enumerating what regulator-blessed foreign-manufactured gear is still riding US networks. [FCC document page](https://www.fcc.gov/document/fcc-announces-conditional-approvals-certain-uas-and-routers-0), [Bureau order DA-26-756 (2026-07-20)](https://docs.fcc.gov/public/attachments/DA-26-756A1.pdf).
- **Check Point CVE-2026-16232 — KEV due date was today (25 Jul).** Assume FCEB agencies were required to be patched by end-of-day; no new advisory landed in the 24h window, but the post-patch hunt (rogue application tokens, admin/policy diffs, SmartConsole/API activity review) remains the actual work. See prior digest for detail.
