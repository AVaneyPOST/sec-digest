## General high-severity

- **Rails Active Storage CVE-2026-66066 — critical (CVSSv4 9.5) unauth arbitrary-file-read escalating to RCE via libvips; broader tier-1 coverage on 02 Aug 2026.** Yesterday's digest flagged this as unverified recency; the CVE itself was published by the Rails team on 29 Jul 2026 (so it is late-July on the primary), but BleepingComputer's technical write-up published 02 Aug 2026 with the RCE-via-libvips detail and the `secret_key_base` rotation guidance. Attack chain: an authenticated or unauthenticated attacker (dependent on Active Storage routing config) submits a crafted path traversal against the Active Storage variant endpoint; when the storage service is `Disk`-backed or when signed-URL enforcement is disabled, the response body includes arbitrary file contents. The escalation to RCE requires libvips as the ActiveStorage variant processor — a maliciously-crafted VIP file exploits a libvips memory-corruption path that reaches code execution. Fixed versions: Active Storage 7.2.3.2 / 8.0.5.1 / 8.1.3.1. Mitigation: upgrade, rotate `secret_key_base` (assume disclosed), audit storage-service configuration for signed-URL enforcement, and validate the libvips version in use. [BleepingComputer coverage 2026-08-02](https://www.bleepingcomputer.com/news/security/rails-patches-critical-active-storage-flaw-with-rce-potential/). Date: CVE 2026-07-29, coverage 2026-08-02. CVE-2026-66066. [CRITICAL — confirmation of prior-digest unverified item]
- **Chromium — enterprise-policy extension force-install on unmanaged devices to be blocked by default.** Chromium change (Gerrit CL landed and covered on 02 Aug 2026) will disable Group Policy / MDM extension force-installs on Chrome installations that are not enrolled with an enterprise. Motivation: closing a persistent browser-hijacker persistence loophole where malware authors write to `HKLM\Software\Policies\Google\Chrome\ExtensionInstallForcelist` (Windows) or push a config profile (macOS) to force a hijacker extension onto a consumer machine. The change does not affect legitimately-enrolled enterprise Chrome installations. Not a vulnerability disclosure, but relevant hardening for anyone tracking the browser-extension supply-chain abuse ecosystem (Adform-class adversaries, MDM-abusing initial-access brokers). [BleepingComputer 2026-08-02](https://www.bleepingcomputer.com/news/google/google-chrome-may-soon-block-new-tab-hijacker-extensions-by-default/). Date: 2026-08-02. [NOTABLE]
