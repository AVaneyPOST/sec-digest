- **Signal RingRTC (CVE-2026-113380, CVSS 9.3) — still relevant for operator-adjacent OTT
  deployments** [NOTABLE]. Disclosed earlier this week; news flow continued into 2026-10-24.
  A malicious call participant can saturate the fixed-size FSM queue (256 entries) so a
  local hang-up fails to tear the call down, leaving audio and possibly video live after
  the UI shows the call ended. Patched in RingRTC 2.72.0 and bundled into current Signal
  clients. Why this matters for a telco practitioner: any enterprise or operator that treats
  Signal as a privileged channel for incident-response bridges should audit client versions
  this week; and the same FSM-queue saturation pattern is a template to look for in your own
  WebRTC / IMS-RTP teardown paths.
  [Malwarebytes writeup](https://www.malwarebytes.com/?p=479546),
  [fdaytalk CVE page](https://www.fdaytalk.com/signal-cve-2026-113380/).

## General high-severity

- **BlackX UEFI bootkit — APT41 attribution (medium confidence), Baton Drop abuse**
  [HIGH]. Bill Toulas on BleepingComputer (2026-10-24). The sample was pulled from an early-
  2026 espionage campaign and is attributed with medium confidence to APT41. It rides the
  pre-patched Baton Drop (CVE-2022-21894) and reportedly also abuses a bypass against the
  CVE-2023-24932 fix, which is still off-by-default. Payload: a driver that disables
  security-related processes and registry callbacks, and tampers with ETW providers to
  defeat EDR telemetry. Mitigations are the usual UEFI hygiene: enforce the Windows SB
  revocation list, apply Microsoft's May 2023 SB updates with the mitigation enabled, and
  monitor for ETW provider manipulation. Primary source was not reachable from this
  environment; details above are from the search summary.
  [BleepingComputer homepage ref](https://www.bleepingcomputer.com/).

- **PHP CVE-2026-115560 — session-handling, still unpatched** [HIGH]. Italy's CERT-AGID
  warned on 2026-10-24 that the four emergency PHP releases of 2026-10-21 (8.2.35 / 8.3.36 /
  8.4.27 / 8.5.12) address only the CVE-2026-109618 / CVE-2026-109619 pair and leave a
  separate session-handling flaw (CVE-2026-115560) open. The earlier `session.upload_progress`
  stopgap is still relevant; mod_php deployments remain the highest-risk configuration.
  No confirmed in-the-wild exploitation of 115560 yet, but it is now the open file on PHP
  until a follow-up release ships. Yesterday's digest flagged 115560 as unverified; the
  2026-10-24 CERT-AGID bulletin elevates it to confirmed-but-unpatched.
  [ts2 writeup citing CERT-AGID](https://ts2.tech/en/phps-new-session-flaw-requires-more-than-a-version-check/).

- **Node.js — CVE-2026-111497 Brotli decoder OOB write → RCE** [HIGH]. Qualys published a
  deeper analysis on 2026-10-23; the fix shipped in the 2026-10-21 Node security release
  (22.23.4, 24.22.1, 26.12.1). Node.js 20.x and older are not fixed. The bug is in the
  bundled Brotli decoder, so builds that link against a system `libbrotli` older than
  google/brotli commit `0ed4268` are also exposed. Priority: Node-based ingress services,
  especially WebSocket and HTTP/2 edges that accept `br` encoding from untrusted peers.
  [Qualys writeup](https://blog.qualys.com/product-tech/2026/10/23/node-js-patches-brotli-remote-code-execution-flaw-find-vulnerable-runtimes-before-attackers-do),
  [Patchstack entry](https://patchstack.com/database/npm/plugin/nodejs/vulnerability/node-js-22-23-4-24-22-1-26-12-1-out-of-bounds-write-in-the-bundled-brotli-decoder-leading-to-remote-code-execution).

- **PingCAP confirms source-code and internal-systems breach (Sept 9 → Oct 7)** [HIGH].
  Vendor security update continues to be referenced in 2026-10-24 coverage. Confirmed by
  PingCAP: a service-account credential was stolen and used to copy data and source code
  between 2026-09-09 and 2026-10-07; discovery on 2026-10-07, credentials rotated 2026-10-14,
  outside IR engaged, no evidence of persistence or impact on data stored *in* TiDB.
  FulcrumSec's claims (10.6 TB, 115k plaintext API keys, 20.6M SQL statements, 413 repos,
  180k affected orgs) remain unverified. Direct implication for anyone running TiDB Cloud or
  using TiDB-adjacent tooling: rotate any API keys you handed to PingCAP integrations;
  review the vendor's post for the authoritative affected-data list.
  [PingCAP trust-hub security update](https://www.pingcap.com/trust-hub/security/security-update-october-2026/),
  [runtimewire summary](https://runtimewire.com/article/pingcap-tidb-cloud-data-exposure-stolen-credentials).
